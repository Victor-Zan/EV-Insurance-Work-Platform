历史绑定与邀请页面/API保留兼容，但不再从登录页引导，不自动迁移或合并已有H5账号/案件。旧邀请仍需人工确认，邀请投递/小程序码能力未验证。新微信账号未采集真实姓名/手机号，也未自动关联历史案件；资料完善及历史案件衔接不在本轮改动内，继续使用原核实规则。

优先配置`VITE_API_BASE_URL=https://<已批准服务>/api/v1`；留空则不外呼。兼容原`VITE_WECHAT_LOGIN_URL`时要求准确以`/api/v1/auth/wechat/login`结尾并从同一地址派生其余接口，不接收任意跨域上传地址。配置不含AppSecret或JWT。认证每次获取新code，重复点击拦截，过期不静默自动登录；H5的绑定/登录提交明确要求在微信小程序完成，H5仅可查看页面（邀请核对如配置服务会调用真实inspect，预览不激活）。

登录响应`user`必须enabled=true、activated=true且只有一个OWNER或REPAIR_SHOP；网点shopId必须有效，车主无shopId。进入业务页/回前台使用`/auth/me`重验，它返回CurrentUser而非LoginResult；身份/网点改变则清会话，网络失败保留有效会话与输入但不显示未经重验的业务页。401清会话并取消旧请求；403保留会话并提示权限；409不自动重放，原命令阻塞直到用户刷新核对后创建新命令；429遵守Retry-After冷却。退出/换账号/失效时清空内存数据、私密下载和队列，旧请求不能写入新账号。

该地址是后续部署服务的接入点，固定对应后端POST `/api/v1/auth/wechat/login`；现有账号密码接口不能代替微信code交换。AppID/AppSecret只通过后端安全配置注入，AppSecret不得放入miniapp前端或其`.env`。前端配置样例为`.env.example`，本地配置已忽略。当前会话仅在内存保存，重启需重新登录，退出清空本页会话和临时图片；本机“退出”没有调用管理员撤销接口，不等于撤销所有会话。

## 公共服务和文件边界

- `src/services/session.ts`：内存会话、账号代次、过期与清理；`auth.ts`：新code、绑定/邀请、重验与路由；`client.ts`：HTTPS同源请求、错误处理和不可变幂等命令。凭据不写本地存储/日志/URL。
- `src/services/upload.ts`：网点维修照片的不可变单图命令及并发2的队列，重试保持文件/派单/类别/幂等键，保留已成功项；OWNER创建上传命令被拒绝。S06用于到店照，S07复用；不连接DEMO编号到真实API。
- `src/services/files.ts`：Bearer头鉴权下载到临时文件再预览，不公开MinIO链接。原生预览success只表示打开，不立刻删文件；S05的OwnerPhoto在销毁/失效时用`releasePrivateFile(path)`只清理自己取得的下载文件，退出时公共服务自动清理全部会话文件。原图不在重试时压缩或替换，服务端仍执行最终格式/大小/阶段/派单/权限检查。
- `src/components/AccountPage.vue`和`src/styles/account.css`：共享H5品牌视觉。表单槽位样式放到应用样式，避免微信组件隔离使按钮退回默认样式；BrandHeader继续与胶囊同排、至少56px高。

## S06网点接单与报价

`ShopHome`提供本店待办、案件搜索/分页、通知/未读及账号ID；`pages/shop-case/index`提供接单/有原因拒单、实际到店、到店异常及继续等待、资料与历史。到店照片由原上传队列处理，只有服务端明确返回本次派单`arrivalPhotoUploaded=true`才开放报价。仅在页面可见、账号重验通过时更新，退出/无权/换派单清理旧数据与私密图片。

`ShopQuotePanel`支持手工逐行报价、原始版本读取和报价专属OCR。JPG/PNG原图每张≤10MiB、最多20张；首次识别外最多明确重新识别3次。候选可新增、替换、忽略或转手填；不覆盖已有人工输入，同一候选不得重复计费。提交先保存每张原图的人工核对快照，再携带返回revision提交报价。失败保留原命令/文件/幂等键，409刷新核对，不自动重新识别。模拟结果明确标识，切换真实供应商后不能采用历史模拟结果。数量是正整数，单价/合计以十进制字符串精确运算，不使用浮点金额。网点不读取正式报价、加价、核损金额或内部资金信息。

## S07网点维修与双方协作

详情“维修”由`ShopRepairPanel`提供维修进度、原图上传/选择、完工提交、冻结证据及收车/评价只读；“结算”只读取本次派单应付目标、累计结算与状态，不读取内部应收、台账/流水/导出，不提供付款按钮。`shop-repair.ts`投影允许字段并使用各领域版本：开修使用quotation.version，进度/完工使用repair.version，不使用工单版本替代。

只有服务端授权与门禁满足才开放维修；正常客服最终授权已自动进入REPAIRING，无二次授权或等待回款。兼容原H5的WAITING_REPAIR_AUTHORIZATION路径时，“维修完成”按既有start-repair接口重验后打开完工照。进度须1—2000字，可不选照片，选择时限本次派单进度照；完工须明确确认并选择1—20张本次派单有效JPG/PNG完工照。原上传队列保留同文件/类别/派单/键，已成功项不重传；服务端冻结照片版本，前端展示冻结时间和版本。已有照片列表受后端当前网点/派单限制，提交时后端再核验上传者、类别及有效状态；客户端无法替代服务端授权。

不确定写入保留本账号内存中的不可变命令，离页重进可按原操作重试；409刷新核对且保留说明/选择，退出或过期清空。页面不可见暂停读取，更多页不被30秒刷新重置；未提交草稿不承诺跨卸载/重启保存。车主沿S05确认收车及一次性可选评价，网点只能读取公开版本，不显示内部纠正原因。管理端、H5和小程序读取相同REST资源，未修改其生产代码或业务规则。
