# 电动车保险维修案件协同平台

面向平台客服、管理员、维修网点和电动车主的保险维修案件协同平台 MVP。本仓库采用前后端分离的 Monorepo，并保持后端为模块化单体。

## 仓库结构

```text
.
├── backend/      # Java 21 + Spring Boot 4.1.1 后端
├── admin-web/    # 管理员与客服桌面端
├── h5-web/       # 维修网点与车主移动 H5
├── infra/        # PostgreSQL 与 MinIO 本地 Docker 配置
└── docs/         # 需求、架构、决策、进度和本地开发文档
```

## 当前状态（2026-10-28）

当前版本已包含阶段 1—8 的案件、派单、报价、维修、资金记录与站内通知能力，以及后续合入的受邀账号开通、统一登录、高德辅助/自动派单、网点报价 OCR 和移动端案件办理。桌面端的新建案件页支持导入微信导出的文件夹或 ZIP，也可粘贴或输入文字并追加现场照片；导入结果仍须人工核对后保存。ZIP 在浏览器内读取，没有新增后端导入接口，也不代表第 13 阶段的智能分类已实现。

高德真实调用与开发模拟目的地均受本机显式配置、权限、预算及资料门禁约束；此前合成测试地点的路线与派单验收不能当作真实合作网点已上线。当前代码的正式迁移已到 V32，保留 OCR Provider 级幂等隔离并持久限制每张原件最多三次主动重新识别；拉取源码不会自动更新正在运行的后端、数据库或前端。运行前按 [本地开发说明](docs/LOCAL_DEVELOPMENT.md) 核对环境、迁移与备份。验证结果、部署状态和限制见 [项目进度](docs/PROGRESS.md) 与 [本机运行说明](docs/LOCAL_RUNTIME.md)。

## 账号与车主关联

新账号由工作人员准备邀请，受邀人通过链接设置密码并激活，再使用**账号和密码**登录。客服可在有权限的正式案件中，根据已核实的车主联系方式为该案件邀请车主开通账号并绑定案件；邀请链接由工作人员通过已核实渠道手动发送。已有普通车主账号可由管理员维护联系手机号，唯一匹配时沿用原有的案件自动关联规则；受邀开通的账号不参与这种仅凭手机号的自动匹配，后续案件需要人工核实并明确绑定。当前没有公众自助手机号注册、短信验证码登录或系统自动发送短信。详见 [受邀开通与统一登录](docs/ACCOUNT_ACTIVATION.md)。

## 最近并入 `main` 的功能

- 维修办理流程：到店照片先于报价；清单上传后自动识别，最多主动重新识别三次；支持固定金额或百分比加价；核损金额弹窗确认后记录，完整授权后直接进入维修，完工照必传。
- 移动端权限与评价：车主、网点不可访问价格库和内部资金流水；网点仅查看本店当前派单结算摘要。车主端简化进度与照片展示，评价采用五颗星，已提交评价保持只读。
- 自动派单与等待接单：事故/接车位置核对、合作或显式开发模拟目的地的道路比较、粗定位标记、目的地快照和待接单简页；最终派单仍由客服显式确认并经过原权限、版本、资格、幂等和审计门禁。见 [自动派单说明](docs/AUTOMATIC_DISPATCH.md)。
- H5 案件办理：案件摘要、流程进度、资料/记录/办理导航统一；网点可在维修流程中区分并上传进度照与完工照，完工后显示冻结证据，原角色和状态机不变。
- OCR Provider 切换：V31 将原件/任务去重和命令幂等限定到 Provider；切换识别供应商时保留原文件及历史证据并创建对应新任务，不覆盖旧结果。
- 高德辅助派单：事故区县独立人工复核、停车位置确认、驾车路线排序、原有人工选择与派单门禁并存；真实调用受持久预算约束，V25/V26 只增量扩展数据库结构，不自动发放调用额度。见 [高德接入说明](docs/AMAP_INTEGRATION.md) 与 [隔离验收记录](docs/AMAP_LIVE_ACCEPTANCE_20261022.md)。
- 桌面端建单资料导入：文件夹或 ZIP 的 TXT/JPG/PNG 读取、文字与图片分开追加、累计照片上限和失败后保留原表单内容；不对图片做 OCR，也不自动完成案件建单。
- 受邀开通与统一登录：服务端按角色引导进入桌面端或 H5，保留既有账号密码及权限范围。见 [账号开通说明](docs/ACCOUNT_ACTIVATION.md)。
- 移动端视觉：登录、首页、导航和案件详情采用与桌面端呼应的暖白与石墨色层次；登录页继续使用移动端原有的充电踏板车图，不替换为桌面端的拆解图。

## 功能范围

管理端面向管理员与客服，移动 H5 面向维修网点与车主。服务端执行四角色 RBAC、本人/本店数据范围、字段脱敏、状态机、乐观锁、幂等和审计。案件支持草稿、正式提交、重复核对、派单与改派；附件存于私有 MinIO，OCR 和地图均有 Mock 路径。报价、核损与三项开修授权、维修交付、人工资金记录和站内通知按各阶段已确认规则运行。平台只记录保险公司、平台与网点之间的资金流程，不实际划转资金；车主不创建案件、不参与报价确认或维修付款。详细规则见 [需求基线](docs/REQUIREMENTS.md) 与 [架构说明](docs/ARCHITECTURE.md)。
