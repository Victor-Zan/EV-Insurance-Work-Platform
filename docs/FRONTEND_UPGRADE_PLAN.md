# 客服与管理员网页版前端升级计划书

日期：2026-10-18。版本：V1.0，待审阅计划稿；视觉偏好已确认。

本轮交付为现状梳理、设计方向与实施计划；没有修改前端代码。本计划中的具体色值、组件参数及动效时长为设计提案，须通过代表页面预览确认，不能视为已经实施或验收通过。

## 1. 已确认目标

用户已确认：

- 范围仅为客服／管理员电脑网页版 `admin-web`，不包含网点、车主 H5。
- 视觉方向为“暖白玻璃 + 石墨灰”，简洁、沉稳、有高级感。
- 动效强度适中，滚动与切换有层次，操作区保持稳定。
- 可以升级配色、组件与视觉细节，减少不必要的提示性文字。
- 业务流程不变，主要排版参考当前版本；先沟通并形成计划书。
- 信息密度略微放松、更舒展，但首屏仍能看到主要任务。
- 保留并精修电动车工程插图，作为平台的视觉特色。

上述偏好已经通过两轮沟通确认；具体页面效果、色值和动效参数将在代表页面预览中校准。

成功标准：用户仍能凭原有习惯找到入口、查看案件和完成操作；整体材质、排版与组件明显更统一；首页能快速找到待办，详情能快速看清当前任务和缺项；滚动和切换有精致反馈，不增加办理等待。

## 3. 视觉方向：温润、清晰、精密

整体印象：暖白画布、清晰的石墨灰文字、轻薄磨砂导航、稳定的白色业务工作区。高级感主要来自一致的比例、边缘、留白、材质和反馈。

### 3.1 配色提案

| 用途 | 提议色值 | 使用规则 |
| --- | --- | --- |
| 页面背景 | `#F5F3EE` | 轻暖白，形成环境底色，避免明显泛黄 |
| 数据工作区 | `#FFFFFF` | 表格、报价、核损、资金和主要表单 |
| 次级表面 | `#FAF8F4` | 分组底、只读区和轻层级 |
| 主要文字 | `#292B2D` | 标题、关键字段、金额 |
| 次要文字 | `#68665F` | 时间、辅助标签、次要信息；不使用过浅小字 |
| 主操作 | `#35383B` | 主按钮与当前导航，配高对比文字 |
| 选中底色 | `#EAE7E0` | 行选中、轻分组，另配明确选中标记 |
| 装饰分隔 | `#DDD9D1` | 分组与非关键分隔；控件可辨识边界另验对比度 |
| 成功／警告／错误 | `#3D6755` / `#8A622A` / `#A04C47` | 只表达真实状态，保留已有绿／黄等业务含义 |

石墨灰承担品牌强调，语义色承担业务判断，不用色彩装饰金额和表格。文字与图标共同表达状态，完成、等待、缺失、作废、只读仍有明确名称。

静态计算：主文字对暖白背景约 12.82:1，次要文字约 5.18:1。玻璃叠加后的实际背景仍须重新检查，不能以这两个静态值代替页面验收。

### 3.2 玻璃材质

| 区域 | 处理方式 |
| --- | --- |
| 全局导航、模块导航、顶部上下文 | 暖白半透明底、轻磨砂、细亮边与微弱阴影；体现前后层次 |
| 登录页、工作台头部 | 允许更明显的玻璃质感，背景只在局部提供柔和明暗变化 |
| 详情摘要、右侧任务框 | 保持现有位置与尺寸，采用偏实的暖白材质，保证小字和材料状态清楚 |
| 对话框、菜单、图片预览外壳 | 外层统一浮层材质，正文与表单区域保持实底；玻璃层不层层叠加 |
| 表格、报价明细、资金记录、长表单、原件 | 不透明表面，避免背景穿透影响核对 |

建议起点：玻璃背景不透明度约 86%—94%，模糊约 10—16px；具体数值由实际背景和性能测试决定。不以扩大模糊和阴影换取“高级感”。

旧浏览器或减少透明度环境使用实体暖白／白色背景。`backdrop-filter` 作用于元素后方，玻璃的可读性需要连同背后内容检查。[MDN：backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter)

### 3.3 排版与组件

- 保留左侧导航、顶部搜索、工作台待办／队列／通知，以及详情顶部流程、正文、右侧任务框的主要位置。
- 在现有布局上略微放松密度：优先增加分组间距、改善标题与控件对齐，表单局部间距可先尝试增加 4px；不等比例放大整页，不增加流程顶栏高度。表格行高在当前基础上小幅试调，以首屏任务和可扫描性验收。
- 中文优先沿用现有系统字体，通过字号、字重与行距建立层级；本阶段不增加外部字体下载。
- 正文以 14px 为基准，页面标题约 24—28px，辅助文字原则上不少于 12px。金额和编号使用等宽数字，金额列右对齐。
- 圆角分级：控件约 6—8px，内容分组约 10—12px，外层玻璃约 14—16px；不把每个小区块都包装成大卡片。
- 主按钮、次按钮、文字动作、危险操作具有稳定区别；一个任务区域突出当前主要动作，按钮名称和点击后果保持原意。
- 统一 Element Plus 与现有原生控件的外观，复用现有组件能力；不为换皮迁移组件库。
- 表格保留列、筛选、稳定排序和分页逻辑。减少多余线条和重背景，明确表头、选中、悬停、禁用与行内操作。
- 输入控件补齐一致的默认、悬停、焦点、错误、只读、禁用、加载状态；占位文字不能替代字段标签。
- 精简纯装饰英文眉题与重复编号，关键区域使用直接、易扫描的中文标题。

### 3.4 工程插图作为平台特色

- 保留现有电动车工程主题，优先精修现有素材的线条、构图、明暗、透明度与裁切，形成一致的视觉语言。
- 登录页保留完整的工程图表达，暖白玻璃与线稿建立前后关系，文字和表单保持清晰。
- 工作台保留辨识度较高的电动车工程图；优化与标题、快捷入口的相对位置，不以增高头部来容纳插图。
- 顶栏保留同主题的淡化局部纹理，与登录页、工作台呼应；核心表格、金额和原件区域保持纯净。
- 调性采用石墨线条和温和灰阶，不添加高饱和光效、漂浮零件或持续背景动画。装饰图不承载业务状态。
- 沿用现有 WebP 等合适资源格式，按实际展示尺寸控制素材体积；需要重新生成或重绘时先在样板阶段确认视觉和资源成本。

## 4. 动效与下滑滚动方案

动效服务于“我点中了哪里、切到了哪里、哪些内容更新了”。业务内容不依赖动画完成才可查看或操作。

| 场景 | 提议效果 | 节奏与边界 |
| --- | --- | --- |
| 按钮、输入、导航 | 色阶、细边与阴影轻微变化，点击有短反馈 | 约 120—180ms；高频提交和金额确认按钮不追随鼠标移动 |
| 页面与任务面板切换 | 短淡入，约 4—8px 位移 | 约 160—220ms；不延迟请求或提交，不为离场动画额外等待 |
| 工作台下滑 | 下方区块首次进入视口时轻柔淡入、上移约 8—12px | 约 240—320ms，最多 40ms 的局部错峰；首屏关键内容立即呈现 |
| 详情正文下滑 | 静态信息组／材料区首次出现时轻入场 | 已聚焦输入、金额、表格行、原件预览和主操作保持稳定；回滚不反复播放 |
| 折叠、展开、弹窗 | 轻微淡入和展开衔接，焦点正确进入与返回 | 不把折叠变为强制新增操作步骤；短动画不妨碍连续点击 |
| 保存、上传、状态更新 | 加载反馈与实际结果提示，局部更新有轻提示 | 状态与金额以真实响应为准，不滚动数字、不先展示虚假成功 |

滚动规则：

1. 页面使用自然滚轮／触控板行为，不接管滚轮，不自动翻屏，不滚动吸附。
2. 详情顶部案件摘要与完整九节点流程保持固定形态，不随滚动缩小、淡出或折叠；右侧任务框保持完整，不增加内部滚动。
3. D-058 的“正文唯一纵向滚动区”列为本次详情阶段的实施建议，明确它尚未完成；与此次视觉升级一起预览确认后再实施。
4. 正文滚动与业务进度严格分离，不随阅读位置改变流程颜色或完成标记，也不恢复已取消的右栏“当前查看”标记。
5. 原件放大使用原有预览能力，锁定背景并在关闭后恢复阅读位置；表格必要横向查看仍保留。
6. 同一节点保存、上传或刷新保持位置与输入；进入另一案件或真实下一节点按既有约定回到相应顶部。
7. 减少动效设置下关闭非必要位移、错峰和滚动入场，所有内容正常呈现；JavaScript 或观察器失效时不能让正文永久透明。

实现优先使用 Vue 现有过渡、CSS 与 `IntersectionObserver`，绑定实际滚动容器并正确清理观察器。不预先增加 GSAP 或平滑滚动依赖。兼容减少动效偏好遵循 [MDN：prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)。

## 5. 提示文字精简规则

判断标准：这句话是否帮助用户决定下一步、理解数据或避免误操作。精简文字不等于删除反馈，也不以悬停提示承载必读信息。

| 类别 | 处理 | 当前页面例子 |
| --- | --- | --- |
| 技术实现说明 | 删除 | “稳定排序”“服务端分页，每页 20 条”“权限以服务端校验为准” |
| 页面标题已表达的信息 | 删除或合并 | “查阅已完成案件与导入的历史档案”，已有对应分区时不重复 |
| 重复权限声明 | 改为必要位置的简短状态 | “仅显示您有权查看的通知”删除；实际只读页面保留“只读” |
| 低频解释与复杂筛选口径 | 放到可点击帮助或紧邻相关控件的说明 | 价格库候选范围与“不自动回退”不能改写成另一种查询逻辑 |
| 上传限制与导入规则 | 简短但在操作前可见 | 文件类型／大小／行数、重复行、无效行、归档后不可修改 |
| 业务阻塞与异常 | 保留在发生位置，写清如何处理 | 缺核损材料、金额未保存、版本已变化、上传失败和重试 |
| 金额、来源与确认后果 | 必须保留 | 元／币种、原始报价与正式报价、核损来源、回款与结算、冲销后果 |

初步文案示例：

- “稳定排序 · 共 20 条” → “共 20 条”。
- “服务端分页，每页 20 条” → 删除文字，保留分页控件。
- “共 8 条；仅显示您有权查看的通知。” → “共 8 条”。
- “只读、只追加；按服务端分页查看关键操作。” → 审计页保留“只读”，删除实现说明。
- 资金操作附近用“仅记账，不实际转账”简洁表达能力边界，不能删除后让用户误以为点击即转账。
- “区域层级与父级由服务端校验；列表按服务端分页。” → 删除通用说明，非法父级时保留具体错误。

以上为提案；实施时逐条建立保留／删除／改写／按需展开清单，并核对原含义。不得通过统一清空所有提示元素来完成精简。

共用组件同时回归客服和管理员。两种角色的可见页面、字段和操作不能因换肤产生变化；H5 保持本轮范围之外。

## 7. 业务与工程边界

- 沿用 Vue 3、TypeScript、Vite、Element Plus 与现有路由；不迁移框架，不增加业务功能或经营统计。
- 案件状态顺序、服务端授权、跨网点数据范围、敏感字段可见性、金额精度与人工录入规则不变。
- 保留维修四项前置、材料校验、原件确认、报价版本、回款／结算顺序、幂等及审计行为。
- 不把原始报价、正式报价和核损金额合并为一个含混的“报价”；不为了视觉统一改动币种、精度、状态或操作名称的含义。
- 工作台未完成队列和历史档案的最新调整继续保留，不借视觉升级重新定义筛选口径。
- 不新增或变更后端接口、数据库迁移与外部服务调用。发现业务缺陷或需改接口时独立记录，不混入换肤任务。
- 现有文档记录本地 8080 运行包与源码存在差异；后续端到端验证使用匹配源码的隔离测试环境，不能把合成界面预览写成真实业务验证通过。
- 本稿不覆盖已确认的 `DESIGN.md` 全文，也不改变 H5 设计。方案正式确认后，将桌面范围的新决定同步到相关设计记录，保留历史结论与适用范围。

## 8. 分阶段实施计划

每阶段交付可查看的页面或文档、验证记录和遗留问题，更新 `PROGRESS.md` 后停止；按仓库约定获得下一阶段确认再继续。

| 阶段 | 工作与交付 | 验证／进入下一阶段条件 |
| --- | --- | --- |
| A：沟通与计划，本轮 | 两轮确认范围、风格、动效、密度与插图；产出本计划 | 计划整体经用户审阅；本轮不改前端 |
| B：代表页面设计预览 | 先补现状截图；制作工作台、案件详情、典型表格／表单三类预览，含滚动和焦点示例 | 同屏比较改前改后；确认材质、密度、插图及动效；预览明确标识示例数据 |
| C：全局视觉与基础组件 | 颜色／字体／间距、导航、登录、按钮、输入、表格和浮层 | 客服／管理员外壳、代表组件全状态、全局影响页面回归；管理端四项门禁 |
| D：案件核心体验 | 工作台、队列、建单、详情九节点、原件对照与滚动结构 | 逐节点业务操作与只读状态回归；桌面矮窗口、金额确认、输入和滚动位置验证 |
| E：其余页面与文案 | 价格库、历史档案、资金查询／导入、投诉／通知、管理员页 | 全页面清单逐项签收，文案逐条核对；导入、版本、权限及空错态回归 |

先做代表页面可以让用户直接判断“暖白玻璃＋石墨灰”的效果，再推广到全站。阶段 B 不接管现有业务页，不把未经确认的视觉提案直接批量套入生产页面。工时在页面样板和具体密度尺度确定后估算，本稿不承诺未经验证的完成日期。

## 9. 验收清单

### 9.1 用户体验与视觉

- 常用入口、当前任务与主要操作仍在熟悉的位置；不新增完成原任务所必需的点击。
- 相同窗口下，顶部装饰不挤压原有关键业务信息；文案减少后仍能判断状态、缺项与下一步。
- 页面比当前略微舒展，首屏仍包含工作台主要待办、详情当前任务与主要操作；工程插图与玻璃协调，保持平台识别度而不遮挡信息。
- 同类按钮、输入、表格、标签、浮层、空态和错误态外观一致；不出现未适配的默认蓝色组件。
- 玻璃背景下所有文字可读；正常文字至少达到 4.5:1，大号文字至少 3:1，按实际合成背景检查。[W3C：文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- 键盘可完成导航、筛选、表单与对话框操作；焦点清晰，不落入不可见区域。

### 9.2 窗口与滚动

- 重点视口：1280×640、1280×720、1366×768、1440×900、1920×1080；以真实浏览器 CSS 视口为准。
- 详情摘要与九节点完整、稳定；右栏在重点桌面视口内完整显示，无内部滚动、遮挡或裁切。
- 正文末项不被操作区遮挡；原件预览关闭、保存、刷新、返回队列均验证原有位置和输入行为。
- 200% 缩放下内容可访问、控件可操作；发生响应式重排时不得通过裁切或过小字号硬塞入页面。
- 表格必要横向滚动只发生在局部，页面不产生非预期的整体横向溢出。

### 9.3 动效与性能

- 首屏任务和表格不等待错峰动画；重复滚动、刷新和切换不反复整页播放。
- 点击反馈及时；动画不延迟业务请求，不引起表单丢焦点、输入丢失或滚动跳动。
- 减少动效、减少透明度及不支持磨砂效果时有完整可用界面；无可见内容被动画永久隐藏。
- 使用浏览器性能记录比较改前改后同类数据、同一窗口的滚动与切换；发现新增持续掉帧、大面积重绘或模糊层叠加时先减轻效果。
- Chrome、Edge 完成核心页面检查；Firefox 至少检查视觉降级和主要操作。仅记录实际检查过的浏览器及版本。

### 9.4 工程与业务回归

- 在 `admin-web` 执行 `npm run lint`、`npm run typecheck`、`npm test`、`npm run build`；按改动补充有意义的行为测试，不用只检查 CSS 字符串的断言代替视觉验收。
- 客服、管理员分别核对入口、可见字段、只读限制与执行权限；涉及权限呈现时回归既有越权、跨店及敏感字段隔离用例。
- 在隔离测试数据上回归建单、派单、报价、核损授权、维修、收车、资金确认和完成；核对合法与非法状态、缺项、重复点击、版本冲突和金额精度。
- 验证上传、原件查看、导入预览／确认、历史版本及异常重试，不写真实业务数据、不调用真实付费 OCR。
- 后端、Flyway、H5、Compose 按实际变更与测试环境需要执行；纯样式／文案阶段未涉及的项目明确注明“不适用，本轮未修改”，不能记作已通过。
- 交付包括页面清单、文案清单、关键截图、动效验证、命令与结果、局限及下一阶段入口。
