## 1. 设计结论

案件详情由“任选功能分区”改为“按当前工作推进”：

- 顶部固定显示案件摘要和进度时间轴。
- 时间轴显示节点、连线、完成时间和当前待办人，节点全部不可点击。点击当前步骤的“继续”时检查并提示缺失信息或材料，不满足前置条件不得进入后续节点。
- 下方只展开当前节点的工作区；未到的节点不显示操作表单。
- 上传、识别、核对跟随对应任务出现，取消独立的“材料与 OCR”入口。
- 每个工作区最多一个强调主操作；等待他人处理时显示等待状态，不放无效的“下一步”。
- 历史记录只读回看。资金、投诉作为关联事项，遵守各自门槛，不混成维修必经步骤。

这里的“每个页面”指进入一个案件后的详情、节点办理和关联事项页面。案件列表包含多个案件，每行显示当前节点、待办人；选中案件的摘要面板显示该案件时间轴。用户管理、价格库等没有案件上下文的页面不放案件时间轴。

## 2. 现状与明确问题

| 证据 | 用户遇到的问题 | 设计处理 |

## 3. 主流程与时间轴

```mermaid
flowchart LR
    A[建单] --> B[派单到店]
    B --> C[网点报价]
    C --> D[报价审核]
    D --> E[保险核损]
    E --> F[维修授权]
    F --> G[维修]
    G --> H[收车]
    H --> I[完成]
```

九个主节点固定显示，节点内的小步骤只在当前工作区展示。节点是进度信息，不是按钮或链接，不接收点击和键盘焦点。已完成结果从“查看记录”打开；未来节点无可进入的表单。前一步未完成时，当前步骤的“继续”会显示缺失项并保持原节点。

| 节点外观 | 含义 | 展示内容 |
| --- | --- | --- |
| 勾选、实线 | 已完成 | 名称、实际完成时间 |
| 亮绿色实心圆 | 轮到当前账号处理 | 名称、当前任务；即使缺材料，只要自己能补齐办理，仍亮绿色 |
| 黄色圆点、等待标记 | 等待其他端或其他角色处理 | 显示“等待网点报价”等具体对象，不以颜色代替说明 |
| 空心圆、浅线 | 尚未到达 | 仅名称，无表单、无操作 |
| 警示符号 | 当前异常或待复核 | “到店异常”“授权待重确认”等准确原因 |

颜色以当前登录账号的真实权限和当前任务判断，不按浏览器或设备判断。例如网点上传报价时，网点显示亮绿色，客服显示黄色；网点提交后，客服审核节点变亮绿色，网点等待审核时显示黄色。管理员无当前业务写权限时显示等待实际办理角色，不因管理员身份变绿。

节点亮绿建议用 `#22C55E`、等待黄用 `#FBBF24`，搭配深色标签；不使用亮底白字。绿色表示轮到自己，不等于已满足提交条件。已完成使用勾选和低强调完成色，未到节点为灰色。关联资金/投诉即使可操作，也不会把仍在等待网点的维修主节点变绿。

时间、待办人来自真实记录，缺失时显示“未记录”，不编造；不只靠颜色区分状态。取消案件停在实际中断位置，后续标记“已终止”，不能画成全部完成。

“完成”明确指已确认收车，**不代表资金结清或投诉关闭**；摘要另显示资金和投诉状态。评价非必填。

## 4. 各节点办理内容

| 节点 | 管理端当前窗口 | 谁处理 | 通过条件与下一步 |
| --- | --- | --- | --- |
| 建单 | 文件夹或文字+照片导入→核对案件号、手机号、牌照/车架号、查勘员、颜色、品牌、车型 | 客服/管理员 | 全部指定信息、至少1张物损照片及重复检查通过；地址不在建单确认，不做照片OCR |
| 派单到店 | 选择网点，随后显示待接单、待到店；到店照随到店任务展示 | 客服派单，网点接单并确认到店；管理员处理既有异常权限内事项 | 当前派单网点实际接单、到店；不提供客服代接单或代到店按钮 |
| 网点报价 | 同步显示网点提交的报价原件、识别信息和最终原始报价；客服端没有报价OCR入口 | 当前网点识别、核对并提交；客服查看核对 | 有当前网点、本次派单有效原始报价；未提交候选不能代替报价。本次包括网点识别、核对、提交的必要页面与接口 |
| 报价审核 | 原始明细只读；固定金额/比例二选一；补齐现场物损照片 | 客服；管理员查看 | 原始报价有效、物损照片有效、加价值合法，生成正式报价新版本 |
| 保险核损 | 正式报价摘要、核损单上传与必要字段OCR、人工核对并录入最终核损金额 | 客服处理；管理员查看 | **拟新增顺序：先有当前正式报价，才开放核损办理**。原件及必要信息齐备并核对后才能继续；OCR失败可人工补录确认，规则见第6节 |
| 维修授权 | 核损摘要，保险确认、客服确认依次办理；授权后等待网点开修 | 客服代录保险确认并执行客服确认；网点开修 | **拟新增顺序：金额和核损单齐备→保险确认→客服确认**；四项齐备后授权，实际开修仍由当前网点执行 |
| 维修 | 进度记录、可选进度照；完工任务中直接显示完工照片和提交窗口 | 网点；客服按现有规则代录进度/完工 | 至少1张当前网点、本次派单上传的有效JPG/PNG完工照；成功后冻结证据，进入待收车 |
| 收车 | 完工证据、收车确认窗口 | 绑定车主或客服；管理员只读 | 明确确认后完成；评价不阻塞 |
| 完成 | 完成时间、维修结果、只读记录及关联资金/投诉状态 | 按各自权限查看或办理独立事项 | 不新增结案按钮；保留客服收车撤回及资金、投诉例外 |

节点内保存材料或金额不等于节点完成。只有服务端确认通过，时间轴才更新。接单、到店、网点报价、开修等由其他角色完成的环节，客服只显示等待和实际记录，不能自行点“已完成”。

控制面板中的“当前查看”只反映本页分组的阅读位置，颜色使用青灰文字/细线；不增加第二条绿黄业务时间轴。“01—03”为同一核损节点内的内容标题，不是独立审批关卡。主操作只在操作区出现，右侧面板不再复制一遍“继续”。

上传完成后，该行变为“核损单 ✓ 已上传（绿色）· 待核对”。只有原件、最终金额等条件满足且已人工核对，点击“继续”才提交本节点业务并进入授权任务。上传、识别成功或保存部分草稿都不会自动确认，也不直接完成节点。保留已有草稿/暂存能力，不为没有暂存接口的步骤暗示已保存。

### “继续”的统一行为

当前账号有办理权限时，“继续”保持可点击以说明缺失项；提交中防重复点击。若材料或字段不齐，展示简短缺失清单并定位到对应输入/上传位置，不进入后续页面，不发起后续业务写操作。服务端仍独立校验全部门槛，前端检查不能替代授权。

例如：“缺少核损单”“最终核损金额未填写”“核损信息尚未核对”。可选材料缺失不列为阻塞；合法缺失原因按已有规则处理。若必须等待其他角色，显示黄色等待状态及对象，不出现可越权的“继续”。“继续”旁可用一句动作说明，如“保存核损，进入维修授权”；需要明确意思的关键按钮使用“确认收车”等业务名称，仍遵守同一检查规则。

### 当前任务

- 主要表单内嵌正文，不同时展开所有阶段；刷新和从待办进入都定位当前任务。
- 上传窗口只显示当前需要的分类，例如“上传核损单”，不出现通用七类下拉框。
- 建单使用文字识别与人工确认面板，不出现OCR操作。报价使用只读对照面板查看网点原件和识别信息，不在客服端重复识别。
- 核损单OCR在文件右侧抽屉打开：原文件、必要字段候选、人工核对、确认。完成后返回核损任务，不跳到独立OCR页面。
- 附件列出文件名、有效/历史、上传时间、预览。替换、作废仅在角色和阶段允许时出现，操作前说明影响。
- 每个对应材料名称后，已成功保存的有效材料显示绿色“✓ 已上传”，缺失显示红色“✕ 缺失”。上传中显示进度，失败显示“上传失败”，不能选中文件后就打勾。
- 上传标记与识别/复核状态分开，例如“核损单 ✓ 已上传 · 待核对”。绿色对勾仅表示材料已上传有效，不自动代表内容齐全或整节点完成。可选项仍标“选填”，缺失不阻塞；旧通知单及其原因仅保留历史，不再是前置要求。
- 点击当前步骤“继续”时，列出具体缺失项及处理人；不能只提示“操作失败”。未来节点不响应点击，权限禁止与材料缺失分别说明。
- 取消、改派、撤回、版本纠正使用专门的原因与确认窗口，不层层叠加弹窗。
- 只有用户主动执行任务按钮才写入；不自动代确认，不自动提交下一节点。

### 历史与关联事项

- “查看记录”打开只读抽屉，按时间展示状态、材料和版本，也可查看已完成节点结果；时间轴本身不承担导航。
- 基本信息折叠在摘要下；有权修改关键字段的人从“更多”进入现有纠正操作。
- 资金、投诉用低强调的文字入口或状态摘要打开关联工作区，保留同一案件标题与时间轴；返回后回到当前节点。
- 全局跨案件资金查询、投诉工作台保留，进入单案后遵守同一门禁，不能成为旁路。

### 5.1 美学方向与技能适配

方向为银白工作台、浅玻璃案件抬头、实体任务面。通过非等分排版、清晰字体层级、精细边缘和滚动反馈增加吸引力，保持连续录入和核对的稳定性。

使用用户指定技能的排版、单强调色、玻璃边缘、完整状态和硬件友好动效原则。结合已确认的工作平台用途，参数为 `DESIGN_VARIANCE=5`、`MOTION_INTENSITY=5`、`VISUAL_DENSITY=7`：布局有层级但不散乱，滚动与短时动效更丰富，数据密度仍适合办公。原有Vue 3、TypeScript、Element Plus和原生CSS继续适用，不采用技能默认的React/Tailwind/Framer Motion栈。

工作台使用稳定的数据分组与分隔线，避免把表单拆成大量营销式Bento卡片。既有台账排序、金额、文字和状态节点不做自动轮换、持续呼吸或漂浮；持续反馈仅用于真实上传/识别处理中，不模拟业务变化。本阶段不引入动画库或外部字体依赖。

### 5.2 栅格、空间与首屏

| 部位 | 排版规范 | 目的 |
| --- | --- | --- |
| 案件工作区 | 内容最大宽1440px；页面内边距宽屏32px、普通桌面24px、窄屏16px | 超宽屏保持阅读距离，小屏仍能办公 |
| 主任务 / 控制面板 | 可用正文宽度≥1100px时非等分两列，主区占余量，右栏280–304px，间距24px | 保证表单和原件核对优先，右栏只做上下文 |
| 常规表单 | 标签在上、输入在下；字段间24px、分组间32px；长文本单列 | 扫描路径一致，减少来回寻找 |
| 材料列表 | 一层列表，每行60–72px；左侧名称/预览，中部状态，右侧动作 | 红叉绿勾紧跟材料，不分散成小卡片 |
| 金额/报价 | 表头与合计实体底；金额右对齐，来源与版本为次级文字 | 易比对金额，减少光效和阴影干扰 |
| 操作区 | 56–64px，左侧仅一句待处理项，右侧主操作 | 长页面仍能找到继续，缺失项不占大段文字 |

首屏包含案件、当前节点、待办人、第一组实际任务及主要办理方向，案件摘要加时间轴建议总高不超过176px。1366×768窗口仍能看到输入或材料行；1280×720下首屏实际工作区不少于360px。不要用大标题、插图或装饰区把表单挤到第二屏。

进入单案办理后，二级模块导航默认收起，保留左侧窄轨道；主动展开时避免半透明导航与正文文字叠读。全局导航仍导航模块，不能作为跳过案件节点的入口。控制面板宽度取可用内容尺寸，不只按整屏宽度判断。

正文左对齐。当前节点有一句任务标题和必要状态，关联资金/投诉使用低强调文字入口。分组由编号、细线和留白建立，不使用“卡片里面再套卡片”。

### 5.3 字体与文案层级

| 层级 | 建议尺寸/字重 | 例子 |
| --- | --- | --- |
| 案件主标题 | 24px/32px，600 | 案件号或案件草稿 |
| 当前任务 | 20px/28px，600 | 保险核损 |
| 分组标题 | 15px/24px，600 | 资料、信息核对 |
| 表单标签/正文 | 14px/22px，400–500 | 最终核损金额（元） |
| 来源/时间/辅助 | 12px/18px，400 | 原件版本、上传时间 |
| 主要金额 | 24px/32px，600，等宽数字 | 核损总额；仅结果摘要突出 |

中文使用系统无衬线字体栈（苹方、微软雅黑、Noto Sans CJK等），数字和编号使用Consolas/SFMono及等宽数字。长编号允许受控换行或复制，不截掉关键区别。字号200%时关键操作不裁切，不使用衬线字体、渐变标题或全页英文大写装饰。

常驻说明只保留当前任务、缺少什么、由谁处理；技术版本号、接口名、英文状态和长规则放记录/帮助。“客服审核与总额加价”改为“审核报价”，“代录保司确认”改为“记录保险确认”，“四项开修条件”改为“授权条件”。不省略金额单位、必填、版本失效影响、权限提示及重要提交说明。

### 5.4 色彩与材料语言

| 用途 | 建议色值 | 规则 |
| --- | --- | --- |
| 页面底 | `#F5F7F6` | 浅灰带同一青灰倾向 |
| 实体数据面 | `#FFFFFF` | 金额、表格、输入和原件核对使用 |
| 次级分组底 | `#EDF1F0` | 只读区、文件预览空态 |
| 主文字 / 次文字 | `#263331` / `#596A65` | 文字以对比度取胜，不用亮色小字 |
| 边界 | `#D6E0DC` | 1px细线，重点分组不依赖重阴影 |
| 品牌强调 | `#526E6E` | 主按钮、焦点、当前阅读分组，只用一个品牌强调色 |
| 自己办理 / 等待他人 | `#22C55E` / `#FBBF24` | 保留用户确认的绿黄节点，只承载流程语义 |
| 已上传 / 材料缺失 | `#15803D` / `#B42318` | 对勾和叉号同时配文字；不把每个缺项画成整块红底 |

品牌色与流程语义色分开：按钮不因节点亮绿色变成荧光绿色，黄色不扩展为装饰背景。当前节点亮绿、待办人标签及绿色对勾各有明确含义，不相互替代。亮绿/黄节点配深色标签，材料图标采用较深绿/红，正常小字保持可读。正常文本按4.5:1、非文本状态图形按3:1目标在最终背景上验收，玻璃变透明后也要检查。

亮绿/黄与浅底的对比度分别约2.12:1/1.55:1，因此节点使用16–20px亮色圆心，分别加2px深绿 `#15803D` / 深黄褐 `#8A5C20` 轮廓，辅以深色标签和等待/办理形状。不能把亮色本身作为唯一可辨边界。基础色计算：正文/页面底约12.20:1、次文字/页面底5.31:1、白字/青灰主按钮5.51:1、材料绿勾/白底5.02:1、红叉/白底6.57:1；玻璃实际叠底仍需实现后复测。

图标采用现有受控SVG或已安装并验证的Vue图标能力，统一1.75px线宽。对勾、叉、等待和文件类型使用矢量图形，不使用表情符号。圆角控件6–8px、数据工作面12px、浮层14–16px；避免所有容器都变成大圆角胶囊。

### 5.5 玻璃拟态的具体位置

| 位置 | 材质与细节 | 使用边界 |
| --- | --- | --- |
| 案件抬头与时间轴 | 白色88–94%透明度，背景模糊12px，1px浅边缘和细内高光 | 只隔开滚动上下文，不让表格文字透到节点下 |
| 右侧任务控制面板 | 白色90–96%，模糊12px，青灰轻投影 | 只放任务、材料、缺项等少量摘要 |
| 底部操作区 | 白色94–98%，模糊8px，上沿细线 | 按钮本身实体底，不能把字段盖住 |
| 历史/OCR抽屉 | 抽屉标题可浅玻璃，正文和原件区域实体白 | 原件与字段对照优先可读 |

玻璃采用一条1px内高光与轻内阴影形成折射边缘，外部投影可用青灰色约8–12%的淡阴影，不用霓虹外光、彩色渐变或跟随鼠标的大光斑。整页不叠满磨砂卡片；滚动时不逐帧动画模糊半径。

低性能设备、不支持模糊、开启减少透明度或强制色彩时，改为不透明白底和边界，层级依旧成立。打印去掉玻璃、固定层与阴影，保留完整资料。原件、输入框、错误文字和金额表格不透明。

### 5.6 鼠标滚动与控制面板下滑

使用浏览器原生滚轮、触控板和键盘滚动。页面正文是主要滚动容器；原件预览有必要时才单独滚动，并保留清晰边界，避免每个小分组都有内滚动条。

| 滚动状态 | 用户看到的变化 | 业务边界 |
| --- | --- | --- |
| 顶部 | 完整案件摘要、九节点时间轴；右侧面板显示当前任务与材料状态 | 只读真实案件进度 |
| 正文向下约64–120px | 车辆等次级摘要渐隐，紧凑案件号/当前节点抬头显现；时间轴保持可见 | 只收拢视觉，不改状态或清空输入 |
| 控制面板抵达固定顶距 | 右侧面板随正文自然下滑，抵达时间轴下方后停驻，距其底部16px | 不浮动到表单上，不跟鼠标追随 |
| 资料→信息核对→结果确认 | 当前阅读分组的青灰细线/标题轻微突出；右栏“当前查看”同步 | 只标阅读位置，不把未来节点点亮或标完成 |
| 主操作的正文位置离开视口 | 本节点底部操作区接续出现，轻微上移淡入 | 只保留一份有效主操作，不复制提交，不因滚动自动提交 |
| 控制面板到当前任务容器底部 | 停在容器边界，不覆盖之后的历史或关联事项 | 不能把当前任务按钮带入另一个业务区 |
| 滚回顶部 | 紧凑抬头退出，完整摘要按相反顺序恢复 | 滚动位置与字段输入保留 |

时间轴始终表达案件进度，不把页面阅读百分比画进节点连线。滚到页尾不解锁下一节点，也不自动勾材料。滚动不自动切案件、展开OCR或跳到新节点，不拦截鼠标滚轮改成横向卷动。

抬头收拢用预留空间、叠层的透明度/位移过渡，不能逐帧改高度把内容顶来顶去。紧凑状态有合理阈值与回切余量，防止滚轮轻微震动时反复闪烁。操作区始终预留底部安全空间，最后一项字段能滚到上方；输入焦点和弹窗出现时调整遮挡关系。

右栏高于可用视口时不强行固定整个面板；内容可正常滚动或仅固定短标题。窄桌面把任务摘要压缩为标题下的实体状态行，取消双重固定栏；小窗口仅保留紧凑案件标题和短当前节点摘要，完整九节点在原位置以纵向形式可查看。

### 5.7 动效规格

| 交互 | 建议动效 | 限制 |
| --- | --- | --- |
| 首次任务内容就绪 | 标题/分组整体透明度与4px位移，180–220ms；至多3组，间隔40ms | 最长整段不超过320ms，页面可立即输入；不逐项让金额飞入 |
| 抬头收拢与恢复 | 180–220ms渐隐/轻位移 | 操作区与正文锚点不跳动 |
| 控制面板停驻 | 原生sticky定位，边缘投影短时淡入160ms | 定位本身不弹跳或延迟跟随 |
| 悬浮操作区出现 | 6px向上位移 + 渐显，180ms | 键盘焦点位置稳定，不覆盖最后字段 |
| 按钮悬停/按压 | 边界与底色150ms；按压最多1px或0.99缩放 | 鼠标不吸附，按钮不逃离点击位置 |
| 上传成功 | 有效文件行一次性浅绿底淡出，对勾线条短时显现180–240ms | 只有服务端保存成功才播放，不弹彩纸、不循环 |
| 缺失项提示 | 错误文字渐显，定位到首个缺项一次180–240ms | 不反复抖动输入框，定位偏移避开sticky抬头 |
| 业务节点完成 | 真实响应后当前/完成标记交替渐显200–240ms | 后续节点直到真实可办理才变绿，不靠动画计时推进 |
| 原件/历史抽屉 | 16px内位移 + 透明度，200–240ms | 保持原位置，关闭后恢复焦点与滚动 |
| 真实加载 | 与内容尺寸一致的骨架；上传显示实际进度，识别显示状态 | 无数据时不制造假百分比；稳定信息不循环闪烁 |

统一缓动建议 `cubic-bezier(0.16, 1, 0.3, 1)`；常规动效只动画 `transform` 和 `opacity`，视觉颜色短过渡不影响布局。不动画宽高、位置属性、整页模糊或阴影扩散；不对每行数据加永久GPU层。

落地优先采用CSS sticky、IntersectionObserver、Vue Transition和有限的CSS/浏览器动画能力。滚动状态不逐帧更新整个案件页面，不每像素发请求；动画及观察器在离页时清理。新页面内容先渲染，动画不能成为路由显示的前置条件；保持上一轮防白屏修复。

开启 `prefers-reduced-motion` 时保留状态切换、sticky和材料标记，去掉位移、平滑自动滚动、绘线及渐次入场。键盘操作不受动效等待影响。

功能整理只让已有能力更易发现和办理，不额外增加智能评分、自动派单、快捷越步、经营假指标或新的角色权限。

### 5.9 完整状态与响应式

加载使用与表单/原件对应的骨架，真实内容可用就立即显示。空材料区保留紧凑上传入口，识别失败显示“手工补录”并保留原件。缺失、版本冲突、网络失败、无权限分别表达，不将全部失败做成一个弹窗；资料和字段不随错误消失。等待状态显示具体处理对象，不用整页黄色遮罩。

宽屏按可用内容宽度展示两列；正文不足1100px取消右栏，两列字段不足以阅读时改单列。1440px及以上优先水平九节点，窄桌面用纵向时间轴；<768px强制单列，优先实际任务，不发生整页横向滚动。网点手机报价使用48px主操作与至少44px触控。

焦点为清楚的青灰轮廓，上传/缺失状态有文字与矢量符号，当前节点使用可访问的步骤说明，等待/成功结果适度播报。固定栏不能遮挡键盘焦点；弹窗关闭回到原操作。长报价表只允许其自身有受控横向滚动。业务加载不依赖退出动画，所有模式保持重试入口。

本轮用文稿和结构示意确认排版；不生成图片。实施前在实际页面验收字体、色彩对比、玻璃可读性、不同滚动位置与动效性能，不把文字规格当作已完成视觉验收。

## 6. 材料与 OCR 随任务归位

| 材料/输入 | 主要出现位置 | 识别及必填规则 |
| --- | --- | --- |
| 建单文字信息 | 建单 | 从文字中提取候选字段并人工确认填入，不调用图片OCR，不静默覆盖已确认字段 |
| NOTICE 通知单 | 建单资料；报价审核前补齐 | 保留文件证据；审核前须有文件或缺失原因，不用通知单OCR代替文字建单 |
| SHOP_QUOTE 网点报价 | 网点报价/报价审核 | 网点OCR并核对后提交；客服同步查看原件、识别信息与原始报价，不再次OCR，不修改网点单价 |
| ASSESSMENT 定损单 | 保险核损 | 可选附件；本轮没有确认新增该类OCR或必填要求 |
| LOSS_ASSESSMENT 核损单 | 保险核损/授权摘要 | OCR提取报案号、保险公司、车牌或车架号、最终核损总额，人工核对后采用；四项授权证据之一 |
| ARRIVAL_PHOTO 到店照 | 派单到店及网点报价资料区 | 不识别，不新增数量门槛 |
| PROGRESS_PHOTO 进度照 | 维修进度 | 可选，不识别 |
| COMPLETION_PHOTO 完工照 | 维修节点的完工任务 | 至少1张，符合当前网点、派单、格式和版本要求 |

七类案件附件沿用PDF/JPG/PNG、单文件10MiB、每类20个有效文件及历史版本保留规则。完工证据保留更严格的图片和归属条件；客服上传其他文件不能冒充网点完工证据。建单文字输入与案件附件分开：已有D-043确认的粘贴文字、TXT、聊天导出文字作为来源，具体文件解析和容量沿用该事项的待确认边界，不把案件附件限额直接套到文本导入。

识别职责分为三条：文字建单、网点报价OCR、客服核损OCR。原文/原件、识别候选、人工修正与最终采用值要能对应追溯；报价必须按同一次提交的原件版本、识别结果和报价版本同步，不能混入旧识别结果。人工确认前不写入正式业务值，识别不会自动完成提交、核损确认或维修授权。

设计期间原基线尚未具备完整网点OCR同步链路；本次实施前已同步团队合并的百度Provider及建单前图片识别能力（D-045、V16），优先复用已实现能力。V3要求的文字建单、网点确认与核损字段采用仍须按新流程实现，不能将旧图片建单入口当作文字建单已完成。第一批不启用外部调用，Mock不能冒充正式识别。

### 文字建单

导入文字→提取候选→显示原文与对应字段→人工确认填入草稿→检查缺失信息→提交正式案件。识别对象为文字，不调用图片OCR；候选冲突需人工选择，不按最后一条消息覆盖。不能提取的字段允许人工补录，原始文字和采用结果保留关联。识别不自动创建正式案件或跳过重复检查。

### 网点报价与客服同步

网点在到店后的报价任务上传原件→OCR提取报价明细候选→核对项目、数量、单价及金额→确认并提交原件、识别记录和原始报价。识别失败或字段缺失可人工补录，必须确认原件；记录识别失败、修正与提交人。正式金额继续按已有精度规则计算，不直接采信图片中的浮点结果。

客服看到同一提交版本的三个部分：原件预览、识别信息、网点核对后的原始报价。人工修正与OCR候选的差异可展开查看。客服无“重新识别报价单”入口，不修改网点单价；后续网点新版本不能覆盖已提交的历史。本次仅重构这条网点必要链路，其他网点页面和车主界面不扩展。

### 核损字段与人工兜底

本版识别范围按用户确认采用：报案号、保险公司、车牌或车架号、最终核损总额；暂不扩展逐项配件/工时识别。最终核损总额仍按原规则必须明确，金额采用前必须人工核对。其他识别字段用于与已有案件匹配，不擅自新增“原件五项全有”的硬性门槛；原件未载明时标记未识别，由客服对照案件确认，不伪造OCR结果。与案件信息冲突必须明确提示，不能覆盖原案件字段。

报价与核损OCR失败、部分成功或字段缺失，都允许人工补录并确认原件后继续；保留原件、原识别结果/失败状态、修正值和确认记录。人工补录不代替核损原件、核损金额、保险确认和客服确认四项授权条件，也不自动跳到下一节点。

**拟限制**：正常操作只上传当前节点所需材料，后续材料不提前开放。前序缺失材料通过当前页“待补材料”按原权限补传，不回退业务状态。已有提前上传文件保留并可只读查看，到了对应节点再核验；不删除、重写或伪造补传记录。此限制对旧端的影响须在第10节确认。

## 7. 防越步规则与真实状态

### 前后端一致

可办理条件为：**角色有权 + 案件可见 + 状态合法 + 前置证据有效 + 派单/业务版本有效**。管理员身份本身不跳过业务门槛。

建议后端提供统一流程视图：当前节点、节点状态、执行者、可执行动作、阻塞原因、材料要求和版本依据。前端不凭URL、按钮点击或枚举大小判断已完成。显示接口不是授权令牌，每个写接口仍在事务中重新校验。

- 直接访问旧 `?section=repair`、修改URL、从通知或跨案件工作台进入，都落到当前节点或合规关联事项，不能解锁未来步骤。
- 直接调用后续接口同样拒绝，返回“请先完成报价审核”等简短原因。
- 防重复点击，继续使用幂等键、期望版本与当前派单版本；冲突后重新读取，保留未提交输入并提示复核。
- 切换案件ID重新读取流程依据，避免上一案件的按钮或授权残留。
- 多人处理后，在页面重新聚焦、手动刷新、提交前后核验节点；服务端拒绝过期操作，无权字段不返回。

## 8. 例外与权限

| 场景 | 页面行为与边界 |
| --- | --- |
| 拒单、改派、到店异常 | 保持派单到店节点，显示异常任务；处理项取现有状态和角色规则 |
| 开修前报价、核损或相关材料修改 | 从受控“修正资料”办理，保留版本；按已有规则清除两项确认、撤销授权；显示最早待重办/复核环节，不提供任意上一步 |
| 开修后修正 | 不开放常规报价/核损编辑，不新增暂停、返工或重开 |
| 收车撤回 | 仅客服、有原因；回待收车，证据冻结和历史保留，重新收车前禁止新增实付 |
| 资金 | 独立记录已发生回款，维修不等回款；付款记账仍需已收车、应付明确、回款结清。只记录、不划款，不从核损金额自动计算网点应付 |
| 投诉 | 开修后按原规则创建，完成后可处理；管理员顺序处理，客服追加纠正。不是维修主线关卡 |
| 管理员 | 全程监督及已有管理/异常操作；不因重构获得客服的核损、材料、OCR、记账或收车权限 |
| 网点与车主 | 本店/本人范围、原有动作和字段限制不扩大，共享后端门禁；本轮只增加已确认的网点报价识别最小链路，其他H5界面后续单独设计，不向外部角色传内部加价、利润 |
