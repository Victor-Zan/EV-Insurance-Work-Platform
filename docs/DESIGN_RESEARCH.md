## 学到的工作方法

1. 先明确页面用途、使用者、信息密度与主要动作，再定视觉规则。
2. 颜色按功能命名：主动作、正文、次要文字、表面、边框、成功/警告/错误；不要只记一组色值。
3. 把字号、间距、圆角、边框和层级形成一套token，页面共享，避免每个组件各写一套。
4. 组件定义默认、悬停、焦点、加载、禁用、错误和只读状态；页面补充加载、空数据、失败与重试。
5. 同一轮先验证一个代表页面/组件，再推广到其他页面。规范变更和实现应同步。
6. 响应式要写出真实布局变化：表格到卡片、操作区位置、字段换行、触控尺寸，而非仅缩小字号。
7. 实际浏览器核验中文、长字段、金额、错误信息及移动布局，测试和构建不能替代视觉检查。

## 对本平台的适配建议（待后续UI任务采用）

建议浅色企业工作台：借鉴IBM的信息结构、Linear的层级与一致性、Stripe的金额排版。它是设计建议，不新增业务规则，不把品牌官网大标题/大幅渐变/深色宣传布局直接用于客服操作界面。颜色与字体具体token尚未定稿。

| 区域 | 后续设计重点 |
| --- | --- |
| 客服/管理员桌面端 | 案件列表筛选、稳定分页、详情分区、表格可读性、一个明确主操作；内部报价和对外金额标签区分清楚 |
| 网点H5 | 当前工单任务优先、附件上传反馈、四项开修条件逐项显示、长报价明细在手机可读 |
| 车主H5 | 允许查看的案件信息与照片清晰，后续收车/评价按阶段7确认；不展示报价、加价或核损金额 |
| 金额 | 原始与外部字段名准确、CNY/元明确、数字右对齐及等宽数字；金额字符串完整显示，不用JS浮点重新计算；展示单价6位且提示行金额为准 |
| 附件/OCR | 分类、有效/历史/作废和版本清楚，上传/下载真实状态；候选信息与人工确认显式区别 |
| 状态与反馈 | 状态有文字及颜色；确认失效与需补条件可解释；COMPLETED/CANCELLED只读有明确呈现 |

后续项目DESIGN.md应包含：视觉基调、语义色、中文字体层级、间距/布局、组件状态、桌面/H5差异、案件标签、附件与报价表格、加载/错误/空数据/只读、可访问性与验证清单。应在获授权的UI任务中结合现有Element Plus/Vant建立自己的规范，再映射代码token；当前只保存学习记录。

## 必须保留的边界

视觉展示服从后端角色/数据/字段权限及已确认流程；隐藏按钮不替代鉴权。四项开修条件不变，不增加回款或网点二次确认。金额精度、分摊、历史不可变、幂等与审计不因视觉重构改变。仍按阶段交付，不以设计学习名义提前实现完整UI重设计、阶段7—8、部署或真实外部服务。
