# 百度手写识别与建单前预填

## 已确认范围与验收

客服尚无案件时上传一张手写单据，后端私有保存并排队识别；程序将有明确标签和来源证据的字段预填到可编辑草稿表单。客服对照原图修正、确认快照，再通过原有草稿与正式提交服务建单。缺失必填项只保存草稿；不自动提交、不覆盖已有案件、不自动派单或产生报价。两张单据各自创建任务，不按姓名或金额自动合并。聊天整包图片不自动 OCR，阶段13聊天导入仍独立待确认。

## 单据内容 → 平台字段（程序候选，均须核对）

| 单据明确标签 | 既有草稿字段 | 映射及限制 |
| --- | --- | --- |
| 客户姓名、客户名称、车主姓名 | ownerName | 必须明确表示客户/车主；联系人或聊天发送人不等于车主 |
| 客户手机号、车主手机号 | ownerPhone | 完整合法数字才预填；多个不同值不选其一 |
| 保险公司 | insuranceCompany | 原文，不猜保险主体 |
| 保险报案号、报案号 | claimNo | 维修单号、清单编号不映射 |
| 报案时间 | claimReportedAt | 完整年月日时分才按中国时间转换；缺时间留待核对 |
| 保单号 | policyNo | 只取明确标签 |
| 车辆品牌、品牌；车型 | vehicleBrand、vehicleModel | 原文，不自动匹配主数据 |
| 车架号、VIN；车牌号；车辆其他标识 | vehicleVin、vehiclePlate、vehicleOtherIdentifier | 保留原文；模糊值提示人工核对 |
| 事故时间 | accidentAt | 完整年月日时分；单据日期、维修日期不映射 |
| 事故地址、事故描述 | accidentAddress、accidentDescription | 只取明确标签 |
| 事故区域 | 独立候选 accidentRegionText | 不凭名称猜区域 ID，由客服选择已有区域 |
| 维修单号、清单编号、单据编号 | 独立 documentNo | 不映射保险报案号/平台编号 |
| 单据日期、维修日期 | 独立 documentDate | 不映射事故时间 |
| 配件名称、数量、单价、金额 | 独立维修明细 items | 程序整理并标注来源；缺数量留空，l 不转 1；不生成正式报价 |
| 合计、共计、总计、总金额 | 独立 amountCandidate | 保留明确数字原文；程序合计单独标注并比较，不冒充原始金额 |

规则处理明确标签/分隔字段或唯一紧邻且横向对齐的文字框。维修表格须同时具备名称、数量、单价和金额的可定位表头；只保留可定位的名称行，数字单元格须与唯一行明确对齐，缺失或跨行歧义留空。自由手写行列、跨行姓名、无标签电话、模糊关系不强行配对，显示原文和警告供人工修正。字段带原始行号及百度坐标，多个不同候选显示冲突且不自动预填。未接入语义模型或外部大模型。

已有百度原文可以由客服显式“重新整理已有原文”产生新的程序候选，不再次外呼；原始响应、初始候选及人工历史保留，新程序版本与后续人工修正分别记录。该操作不自动确认或写正式业务。

## 官方资料与限制

- [手写文字识别](https://ai.baidu.com/ai-doc/OCR/hk3h7y2qq)：后端 handwriting 接口，概率/坐标以实际返回为准，不是专用结构化单据识别。
- [鉴权与调用](https://ai.baidu.com/ai-doc/OCR/Ck3h7y2ia)、[错误码](https://ai.baidu.com/ai-doc/OCR/dk3h7y5vr)。手写专页与通用页编码大小表述不同，本版保守限制 URL 编码后的请求为 4 MiB；图片边长 15–4096，支持 JPEG/PNG，拒绝损坏、空白、PDF 和超限，不静默截断或缩图。平台原附件 10 MiB 限制不代表供应商可识别。

真实模式须显式配置 OCR_PROVIDER=BAIDU_HANDWRITING_V1；默认 MOCK_V1。凭据仅来自后端 BAIDU_OCR_API_KEY、BAIDU_OCR_SECRET_KEY 环境变量（空值不能启用真实识别），不得放入命令文字、前端或 Git。本轮用户2026-10-14授权使用其提供凭据并提供本机私密配置，实际只在内存加载，不声明凭据已轮换。Token 只缓存于后端内存，提前失效并串行刷新；失效错误最多刷新一次。网络不自动重试；可能已计费的失败必须由客服显式决定重试。重启或租约过期不会自动重复百度请求，外部 API 无法保证 exactly-once。

本轮最多两次真实 OCR 请求，仅限用户指定本地样本；不自动重试、不调用额外接口。隔离模式设 BAIDU_OCR_TOKEN_RETRY_ENABLED=false、BAIDU_OCR_MAX_CALLS_PER_PROCESS=2、OCR_MAX_ATTEMPTS=1；GET ocr/configuration 的 processRequestCounts 分别报告进程内鉴权与 OCR 请求次数。计数跨重启不保留，验收中不得重启来增加预算。未成功真实识别及端到端验收时须记为未验证。样本与识别全文不得进入 Git、日志或公开报告。完整 JPEG 允许结束标记后的应用尾部；保留原字节和摘要，不裁剪、不静默截断，解码告警或缺失结束标记仍拒绝。
