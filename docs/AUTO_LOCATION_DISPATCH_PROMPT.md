确认日期：2026-10-25。状态：需求规划已确认，尚未实施。

本文件供用户今后明确要求开发时使用。整理、阅读或引用本文档，不代表现在可以修改功能、部署运行包、导入资料或调用真实高德接口。

## 使用方式

未来可向开发代理发送：

> 请按 `docs/AUTO_LOCATION_DISPATCH_PROMPT.md` 实施地址自动定位与维修网点推荐。先核对当前代码、运行版本和数据前提，按本文已确认的流程开发并验证，保留工作区已有修改。真实供应商调用和运行环境切换，按当次明确授权范围执行。

下文是实施任务及验收依据。

## 一、目标与已确认的交互

减少客服在“建单 → 派单”之间重复填写和重复确认的操作。

正常流程为：第一步保存事故地址 → 进入第二部分自动定位 → 自动匹配省市区 → 自动计算合格维修网点的道路距离 → 自动预选最近网点 → 客服最后核对并点击一次派单。

用户已明确确认：

1. 默认车辆仍在事故地点，事故地点可作为接车位置的初始来源；车辆已转移时，客服通过“车辆已转移／修改接车位置”更正。
2. 第一部分没有可用地址时，在第二部分提供一处地址补填入口。填完按回车或离开输入框，触发定位和推荐，不再要求另点搜索按钮。
3. 自动操作到推荐和预填为止，正式派单仍由客服最后确认。系统不得自动向网点派单。
4. 正常成功路径不再分别要求选择事故省市区、保存事故区县、重复选择停车城市区县、确认位置、查询网点、点击第一家网点。
5. 地址歧义、定位不够精确、行政信息冲突、无合格网点或服务失败时，才展开对应的补充或更正操作。

示例：“宝安区自由路”可以匹配广东省／深圳市／宝安区，但只有道路名称不必然代表准确接车入口。行政区匹配成功和接车点足够精确必须分别判断。

## 二、第一部分与第二部分的数据衔接

- 使用第一步已保存、已接受的事故地址及结构化区域信息；未采纳的OCR／聊天导入候选不能当成已确认案件资料。
- 保留原始地址文本和来源。规范化地址、省市区、坐标及精度应能追溯到本次解析，不能悄悄改写原始资料。
- 先利用本地行政区划和已有案件上下文补齐唯一明确的父链。例如在广东范围内唯一匹配“宝安区”时，可带出深圳市和广东省；遇到重名、信息缺失或冲突，不取第一项冒充确定结果。
- 结合有效的地址上下文调用高德，复核返回的省市区和adcode；不能仅凭“接口返回成功”就采用结果。
- 原事故地址与接车位置在数据上继续独立。默认接车位置来自事故地址；接车位置后来改变，不能反向覆盖事故地址、事故区县或服务资格。
- 已经人工更正并保存的接车位置优先于默认值。重新进入页面、更新案件资料或迟到的接口响应，不能覆盖该更正。
- 尚未进入允许派单的案件阶段时，不得为了运行自动推荐而跳过建单提交及原有必填、材料和状态校验。

## 三、自动触发与防重复

- 首次进入允许派单的第二部分，有可用事故地址、没有人工更正接车位置且没有本次输入的有效结果时，自动执行定位与推荐。
- 没有地址时先等待补填，不对空地址、占位文字或输入中的半成品发请求。
- 手填地址后，回车或失焦进入同一条处理链。回车引起的后续失焦只能触发一次；内容未改变时再次聚焦、失焦不重复请求。
- 正常链路一次接续完成定位和道路推荐，不再增加“继续计算”确认按钮。
- 同一案件、同一有效输入复用有效结果和在途任务。刷新、重新挂载、切换标签页不能成为重复定位和逐店算路的理由；去重不能只依赖组件内变量。
- 请求与案件、操作者、地址版本和相关网点资料绑定。地址被修改、接车位置更正或请求已失效时，旧响应不得填回字段、恢复旧选择或写入确认状态。
- 已失败、结果过期、额度不足或权限异常时，不自动循环重试、换接口补搜或静默重新计费。保留输入并给出明确的重试／重新计算入口。
- 推荐有效期、单次候选上限和调用限速沿用经核对的当前实现；不得为实现自动化而悄悄延长有效期或提高上限。

## 四、自动定位的成功与异常条件

- 仅在地址结果唯一、行政区一致且接车精度满足实际业务时，自动继续计算和预填。
- 仅有区县中心、城市中心、道路级估算位置，或多个同名地点时，应显示“请补充门牌／地标或校正接车点”，不得标为精确接车位置。
- 提供一处更正入口，允许补充地址或按现有地图能力校正位置；不要求重新填写已确定的整个省市区链条。
- 高德返回的区域与建单事故信息冲突时，保留原信息并指出冲突，不自动以停车点、推荐网点或供应商结果改写事故事实。
- 车辆转移后，仍按原事故区县筛选服务资格，按更正后的接车位置计算距离。
- 超出目前支持的广东区域、行政区资料缺失，以及东莞／中山没有县级节点等情况应明确说明，不伪造区县或擅自扩大业务范围。

## 五、维修网点范围与“最近”的定义

- 本功能候选来自系统已导入／维护的合作维修网点，不扩大到公开POI门店来源。
- 复用现有网点启用、事故服务区域、品牌车型适配、真实有效位置等资格规则。不能为凑出最近网点而修改案件事实、猜车型或扩大网点服务范围。
- 复用已核实的网点坐标。只有门店名称、模糊地址、模拟坐标或无坐标时，应提示维护资料，不能用城市中心或Mock点计算真实推荐。
- 原有市级服务关系不得自动扩展成全部区县服务关系；资料维护应通过既有管理员权限和审计流程进行。
- 使用“实际接车位置 → 网点”的高德驾车道路距离，沿用当前已确认路线策略，按米数从小到大排序；相同距离使用稳定次序。
- “最近”只针对本次资格与计算范围内、完成有效道路计算的候选，不把直线距离、时间或未计算的远近猜测当成道路最近。
- 全部相关合格候选能够完成有效比较时，自动预选第一家，展示网点名称、地址和道路距离，并允许客服换店。
- 存在关键坐标缺失、候选超过现有限制或道路计算失败时，说明比较范围与缺项，不把不完整比较标成已确定最近，不静默截断候选再自动确认。
- 无合格网点时保留位置，提示维护资料并保留已有人工处理路径。不得伪造一个推荐网点。

## 六、界面与最后一次确认

正常路径以位置摘要和网点摘要为主，例如：

```text
事故地点：广东省 / 深圳市 / 宝安区 / 自由路具体门牌或入口
接车位置：同事故地点                       修改接车位置
推荐网点：某已核实合作维修网点 · 驾车道路距离约 X km
                                            更换网点
                           核对位置和网点并派单
```

- 原独立“事故区县”填写大块和重复城市区县选择，不再在正常成功路径中展开。保留可访问的修改入口及异常提示，不删除必要的数据校验。
- 已明确的信息自动带入；缺少或有冲突的项目才要求填写，不能把旧的整套核对表单藏到新按钮后再次全部要求操作。
- 定位、计算中清楚显示进度并防止重复提交；失败保留已输入地址和其他建单信息。
- 最后一次确认承接本次必要的区域／接车位置保存和正式派单，复用原应用服务、状态机、版本、幂等及审计；用户无需分别提交每一步。
- 服务端重新校验位置、案件版本、推荐有效性、网点资格及当前选择。客户端显示已选，不等于服务端已经授权派单。
- 业务写入遵守现有事务边界；失败不得被页面显示为派单成功，亦不得绕过原位置确认门禁直接改Mapper。更正失败时保留可恢复的输入。
- 初次派单是本轮正常路径；已有派单的改派继续使用原权限和显式操作，不因自动推荐在后台改派。

## 七、高德配置与调用边界

- 地址解析和道路计算使用后端Web服务Key。JS Key／jscode用于可视底图，两者配置与用途分开；没有底图不应直接阻止具备条件的后端定位和算路。
- 自动调用只是交互方式变更，不代表新的调用预算授权。沿用实际运行环境的CONTROLLED／PROVIDER策略、限流、超时及额度检查，不重置或补发旧额度。
- 实施时核对高德接口权限和候选数带来的调用量。已有网点坐标可复用；不要每次案件推荐都重新解析全部门店地址。
- Web服务Key和jscode留在后端，不进入VITE变量、浏览器代码、普通日志、文档或Git。
- JS底图仍沿用现有明确加载机制，本功能不要求打开页面就自动下载底图SDK，不读取设备定位。
- 开发验收优先使用Mock及合成资料。真实联网、测试地址和预算按未来执行时用户明确授权开展；本规划本身不授权真实调用或付费操作。

## 九、验收条件

| 场景 | 必须达到的结果 |
| --- | --- |
| 建单已保存完整且唯一的事故地址 | 进入第二部分自动定位、带出省市区、完成道路比较并预选网点；正常情况下只需最终确认派单 |
| 地址为“宝安区自由路”但只定位到道路 | 可带出明确行政区，提示补门牌／地标或校点，不假装接车入口已确定 |
| 第一步没有地址 | 第二部分仅在补填完成、回车或失焦后触发，不对空值调用 |
| 回车后紧接失焦、同值重复失焦 | 同一输入只产生一条处理链，不重复调用或派单 |
| 页面刷新／重进、请求仍在途 | 复用相应有效结果／任务；不由组件重新挂载重复算路 |
| 地址多解、区域冲突或供应商失败 | 保留原始资料和输入，提示具体待处理项，不自动选第一项或无限重试 |
| 车辆已转移 | 更正接车位置后重算；事故区县不变，旧距离与旧预选失效 |
| 修改地址时旧响应晚到 | 旧响应不能覆盖新输入、人工更正或最新网点选择 |
| 网点未启用、不匹配区域／车型、缺真实坐标 | 原资格校验有效，不伪造坐标、扩大服务范围或认定最近 |
| 路线部分失败、候选超过上限或预算不足 | 明确范围与缺项，不截断冒充全体最近，不补发预算 |
| 自动预选后客服换店 | 最终提交的是客服选择，旧响应／刷新不会悄悄改回第一家 |
| 最终确认重复点击、并发改案、资格已变化 | 幂等、版本与服务端复核生效，不产生重复派单或越权 |
| 无底图但Web服务可用 | 地址与道路推荐可独立工作，底图关闭原因可见 |
| 非客服、跨网点、已派单或不允许派单的阶段 | 保持原权限和状态限制，不触发越权自动计算或后台改派 |
