# 公开两轮电动自行车维修候选与本案临时网点

入口：客服工单详情→派单到店→确认并保存车辆停车位置→智能分拨候选。公开候选不以是否合作、是否已在平台建档作为搜索条件，不再要求先录入合作网点才能发现门店。原合作网点推荐折叠保留，原人工派单及管理员账号管理不变。

## 搜索与分类

- 明确点击查询才调用高德Web服务v5/place/around；固定关键词“电动自行车维修”，半径10000米、一页最多20条，翻页单独点击并计次。不自动全页扫描、扩圈、换关键词或重试。此接口只传搜索中心坐标及必要固定参数，不发姓名、手机、车牌或案件资料。
- 不把city=广东省当硬限制；返回结果按pname=广东省及44开头行政码复核，省外丢弃。搜索允许跨停车区县/城市的省内邻近结果；事故区县不会随停车位置或搜索结果变更。
- 用返回名称与类型保守筛选，排除无两轮依据的明确汽车维修、纯销售、充电/外卖柜等无维修依据结果。两轮维修线索不等于已核实能力；电动车/摩托车/自行车维修边界结果显示待核实。既不宣称分类100%准确，也不静默把汽车维修改成两轮维修。
- 供应商关键词检索并非完整门店目录，也不保证前20条就是道路最近20家。页面说明本次半径/页次/受限集合，不声称全省最近。未收录、关键词未命中、纯销售兼营但未注明维修等门店可能漏掉，可由客服核实后手动补充。

官方参数：https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch 。POI的distance不是道路距离，本功能不拿它排序。

## 道路与用量

本功能默认关闭，PUBLIC_WORKSHOP_ENABLED=true才启用。共享既有独立POI_SEARCH剩余槽位，与停车地址搜索合计仍为原10次，不新增或补次数。手动查门店地址、公开查询、翻页都计一次搜索；确认和读取缓存不调用搜索。高德底图加载/平移资源另按既有JS资源机制，不属于这些Web服务槽位。

明确勾选比较集合，再点击确认道路计算；原DRIVING剩余额度须容纳整个集合，先持久预留后逐店调用，不截断成前若干家。最多20个本页公开候选及5个手动候选；额度不足时由客服明确减少比较数量。方向车辆→门店，v5驾车策略32，按米数升序、名称和候选ID稳定次序；无路线/失败/超时距离留空，不填0、不伪造。最多60秒执行窗口，未开始调用的保留未知并释放未使用预留；已尝试不归还。供应商失败不自动降级Mock。

道路结果2分钟后显示过期，不自动重算。位置候选及公开结果受原10分钟停车会话和案件版本控制。请求幂等元数据持久化，进程重启/缓存丢失不能靠相同操作键重发外呼；需要用户明确新的查询意图及现有剩余额度，不恢复已耗额度。

## 手动补充与正式派单

“手动输入网点”填写名称、广东城市/区县及地址，经原位置服务搜索并明确确认门店地址，然后加入候选。不要求门店已出现在本页公开结果，可在本省其他明确位置手动补充；页面注明可能不在本次10公里范围。地图未收录且无法核实具体位置的门店，不伪造坐标或道路距离。

选择候选后，客服核实门店可维修两轮电动自行车、愿意处理本案及可登记的名称/地址，才可“登记并选择本案临时网点”。该动作不是派单、不建账号。临时门店名称带【临时／仅本案】、代码TMP-，单独绑定本案和登记时已核实的事故区县，仅建立该区服务关系，写SHOP_CREATE与SERVICE_REGION_CHANGE审计；不能据此给全平台扩服务范围或车型能力。发现同名同址既有网点不自动合并，提示使用原网点入口/管理员核实。

最后点击原派单/改派按钮，沿原业务服务执行地址确认、状态、区域、停用、重复、幂等、并发和审计，进入待接单。绑定关系受服务端及数据库双重保护；其他案件不能使用该临时网点。普通网点和车主不得读取公开搜索/内部位置接口。管理员仍按原流程为实际门店创建/邀请网点账号，未开通账号前不能声称门店已在线接单；本功能不扩大客服通用网点或用户管理权限，不发送外部通知。

供应商候选、坐标和道路结果仅在受控内存短期保留。正式登记存储客服核实的业务名称/地址并保留PUBLIC_POI_VERIFIED/MANUAL_VERIFIED来源，不永久保存原供应商返回、坐标或路线轨迹，不构建可复用的POI地理数据库。企业仍需确认供应商授权与正式资料留存适用性，本实现不作合规结论。

## 迁移与API

本轮运行基线业务V26，远程main另有V27/V28，本功能不改旧SQL、不偷偷升级其他需求。新增db/public-workshop/V1__case_scoped_workshops.sql，当前业务schema内采用独立flyway_public_workshop_history（首次baseline 0）追加case_workshop_binding、public_workshop_operation，以及限定临时门店案件范围的work_order/work_order_assignment触发器。只在显式启用时运行；没有默认门店/案件/账号/额度种子。旧主历史与两份预算历史不变，后续整合main须保留各自迁移历史并另行审查，不修复/重置旧库。

- GET /api/v1/maps/public-workshops/configuration：启用和只读剩余额度。
- POST /search：caseId/locationToken/page，Idempotency-Key必需。一页最多20家，无路线调用。
- POST /manual：caseId/queryId可空/parkingToken/shopLocationToken/name，Idempotency-Key必需。
- POST /routes：queryId/selected候选ID列表，Idempotency-Key必需，先检查整个集合额度。
- GET /{id}：本人候选及短期道路结果，不外呼。
- POST /temporary-shop：queryId/candidateId/核实name/address/verified=true，Idempotency-Key必需。专门本案登记，不开放任意角色或账号分配。

全部位于现有客服专用maps授权下，服务端复核当前角色、账号状态、案件范围、版本、停车会话；管理员/网点/车主不能借此获得客服操作权限。记录只含ID、摘要、数量和状态的审计，密钥、关键词、坐标、完整电话不入普通日志。

本轮按用户要求不做功能检验/自动测试/真实供应商联调，仅编译打包。分类准确性、真实搜索、道路排序、临时门店完整派单及网点接单均未验收，不能把编译/启动成功写成真实可用通过。
