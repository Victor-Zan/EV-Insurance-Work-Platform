# 经营看板工程学习笔记

2026-11-11。之后每项工程交付都按“做了什么、为什么这样做、如何验证、可以学到什么”提供教学总结。

## 1. 先定义统计口径，再写图表

同一张工单会经历完成、冲销、再次完成。直接数历史里的“完成”记录会重复计算。本次先限定工单当前仍已完成，再取最新完成事件。日期、网点和金额都寻找该次完成对应的依据。

可以从 `backend/src/main/resources/db/migration/V36__business_analytics.sql` 阅读这一步。这里的数据库视图是一条可复用查询，它不会复制一份新的业务金额表。Flyway 负责让数据库变更按版本执行，已应用的迁移应通过下一版本继续演进。

缺少依据表示无法可靠确定完成时应收、应付或承修网点。它仍是一张完成工单，但不能猜一个金额混入利润，所以页面同时显示完成量、已核算量和待核算量。

## 2. 用同一集合计算金额

保险应收、网点应付、平台盈利和毛利率必须来自同一批已核算工单。总毛利率等于总盈利除以总应收。例如两单应收分别为 100 和 900，盈利均为 10，总毛利率是 20/1000=2%，不能把 10% 和约 1.11% 取平均。

SQL 的 NUMERIC 执行精确金额运算，接口以字符串传输，避免金额过早进入浮点运算。只有画图时把数值转换为图表所需坐标。阅读入口是 `backend/src/main/resources/mapper/funds/AnalyticsMapper.xml`。

## 3. 页面状态与接口数据分工

Vue 保存日期、视图、网点、客服、分页和明细下钻状态。状态变化触发接口请求，ECharts 根据返回数据绘图。用户快速切换条件时，请求可能乱序返回，因此用递增请求序号阻止旧结果覆盖新条件。

总日期与明细日期分开保存，用户可以查看某一天的工单，同时保留整个期间的总览。阅读入口是 `admin-web/src/features/funds/AnalyticsView.vue`，图表生命周期集中在 `AnalyticsChart.vue`，离开页面时释放图表和尺寸监听。

## 4. 权限必须由后端落实

前端隐藏客服选择框只能改善操作界面。真正的数据保护在 `AnalyticsService.java`：客服查询强制加本人 created_by 条件，传入别人的 ID 也会被拒绝。管理员的三种分析视图与客服本人的经营页是不同的权限范围。

## 5. 三类验证各解决一种问题

前端测试检查自动查询、旧响应隔离和客服请求范围；真实 PostgreSQL 集成测试检查金额、零分母、负盈利、缺依据、跨月、冲销、再次完成和越权；浏览器验收检查图表、排版及真实交互。构建成功只证明代码能够产出部署文件，不能代替这些业务验证。

本轮命令与结果记录在 PROGRESS。建议阅读顺序为本页 → REQUIREMENTS 的经营规则 → SQL 视图 → AnalyticsService → AnalyticsView → 新增测试，沿一张工单的数据流理解整个功能。

## 6. 有索引也要看它执行了多少次

补测用同一批十万张合成工单对比两种查询。客服查询限定创建者和月份，单条 SQL 约 38–46 毫秒；平台查全年时，指标、趋势和明细各约 3 秒。执行计划显示，平台查询有索引可用，但每次仍要对大量工单分别定位完成、确认和资金依据。阅读 `EXPLAIN ANALYZE` 时，把每一步的实际行数和 `loops` 放在一起看，才能找出主要成本。

同样，专项集成测试通过与全量回归通过是两回事。专项验证经营规则；全量还能找出旧库升级测试仍指向 V35，以及其他模块的初始化问题。遇到几十个报错时，先定位共同的首个错误，再按原因处理，避免把同一处初始化失败误当成几十个业务缺陷。
