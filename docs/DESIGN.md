- 日期：2026-10-10。
- 状态：已确认（2026-10-10）；用于约束提示词 10 管理端与提示词 11 H5 的实现。
- 本阶段边界：只确认视觉系统、信息架构、关键页面、交互、动效和响应式规范；不改 `admin-web`、`h5-web` 业务页面，不改 API、状态机、角色、字段可见性或业务规则。

## 2. 设计结论

设计方向定为“银白命令轨道与案件主从工作区”：浅色、克制、长时间办公友好。桌面端以窄命令轨道、当前模块玻璃导航舱和实体数据工作区建立层级；案件模块在宽屏使用“案件队列 + 选中案件工作面板”，复杂编辑继续进入完整详情。H5 与桌面端共享颜色、字体、状态语言和组件语义，但按网点、车主分别组织首页任务。

采用 `design-taste-frontend-v1` 的单一强调色、反卡片滥用、完整交互状态、硬件友好动画和可访问性原则，并做以下业务化降级：

- `DESIGN_VARIANCE` 从 8 调整为约 5：主从布局允许不对称，但表格、金额、表单维持严格网格。
- `MOTION_INTENSITY` 从 6 调整为约 3：无常驻循环动画；只保留短时状态反馈和可选、有限的流程导览。
- `VISUAL_DENSITY` 从 4 调整为桌面 7、H5 5：客服可高效扫描，移动端仍保留触控空间。
- 不使用 React、Tailwind、Framer Motion 或 Skill 指定的 React 图标包。项目继续使用 Vue 3、Element Plus、Vant 和原生 CSS token。
- 不使用超大圆角、Bento 营销卡片、彩色渐变、霓虹、炫光、持续漂浮、自动轮播或横向滚动接管。

## 3. 核心设计原则

1. **先任务，后装饰**：页面首屏必须回答“当前是什么状态、为什么被阻塞、下一步谁能做什么”。
2. **真实能力优先**：首页只展示现有案件、待办、通知、价格库和管理能力；没有聚合 API 就不画经营统计。
3. **权限即信息架构**：不同角色不仅隐藏按钮，连页面入口、字段名、空态和导出入口也必须按服务端权限分开。
4. **主从但不塞满**：选中案件面板用于摘要、状态、阻塞条件、最近历史和单一步骤；长表单、批量导入、报价明细、OCR 复核、资金核对进入完整页面。
5. **实体数据面优先**：表格、长表单、报价/资金明细使用不透明白色表面；玻璃只用于导航、上下文和浮层。
6. **状态不能只靠颜色**：状态同时有文字、图标/形状和必要说明；金额、版本、只读、已作废、已冲销必须明确写出。
7. **审计友好**：涉及金额、版本、确认、撤回、冲销、改派和取消时，在提交前说明影响，在成功后给出可追溯结果。
8. **移动端单主操作**：同一屏底部最多一个强调主操作；危险操作和次要动作不得与主操作等权。

## 4. 视觉系统

### 4.1 语义色 token

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--color-canvas` | `#F7F8F8` | 页面底色、低对比背景 |
| `--color-surface` | `#FFFFFF` | 表格、表单、正文、金额明细 |
| `--color-surface-muted` | `#ECEEEF` | 禁用区、分组底、骨架屏 |
| `--color-border` | `#D5D9DA` | 默认边框、分隔线 |
| `--color-border-strong` | `#B8BEC0` | 控件悬停、重点分隔 |
| `--color-text` | `#2C3133` | 主文字；白底对比度约 13.18:1 |
| `--color-text-secondary` | `#667074` | 次要文字；珍珠白底约 4.77:1 |
| `--color-accent` | `#526E6E` | 当前导航、主操作、焦点；白字对比度约 5.51:1 |
| `--color-accent-soft` | `#E4EAEA` | 选中行、轻提示，不承载小号低对比文字 |
| `--color-success` | `#3F6D62` | 已满足、有效、完成；白底约 5.87:1 |
| `--color-success-soft` | `#E7F0ED` | 成功背景 |
| `--color-warning` | `#8A5C20` | 待确认、需人工核对、逾期 |
| `--color-warning-soft` | `#F2EBDD` | 警告背景 |
| `--color-danger` | `#A34E49` | 错误、取消、作废、冲销；白底约 5.61:1 |
| `--color-danger-soft` | `#F5E8E7` | 错误背景 |
| `--color-info` | `#526E6E` | 一般信息，复用唯一强调色 |

约束：

- 正常业务页面只使用一个品牌强调色 `#526E6E`。成功、警告、错误是语义色，不作为装饰色。
- `#6F777A` 可用于白色表面的 14px 及以上次要文字；珍珠白底上的正常字号改用 `#667074`，避免对比度不足。
- 禁止纯黑、紫蓝渐变、霓虹外发光和大面积彩色背景。
- 颜色不能单独表达维修授权、文件状态、投诉状态、资金状态或表单错误。

### 4.2 字体与数字

```css
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
  "Microsoft YaHei", "Noto Sans CJK SC", sans-serif;
--font-mono: "SFMono-Regular", Consolas, "Liberation Mono", monospace;
```

- 不再使用当前未显式安装的 `Inter`；第一版不依赖外部字体下载。
- 桌面正文 14px/22px，辅助文字 12px/18px，页面标题 24—28px/34px，区块标题 18px/26px。
- H5 正文 15px/23px，辅助文字 12—13px，页面标题 22—24px；系统字体缩放到 200% 时仍可操作。
- 金额、案件号、流水号、日期时间、版本号使用等宽数字或 `font-variant-numeric: tabular-nums`；普通中文不整页使用等宽字体。
- 金额由 API 十进制字符串格式化显示，前端不得用二进制浮点重新计算。上下文写明 `CNY / 元`；金额列右对齐。
- 原始单价最多 2 位；正式对外展示单价保留 6 位；行金额是精确依据。界面不得暗示展示单价乘数量一定等于行金额。
- 手机号、车辆标识和内部字段继续使用服务端返回的脱敏结果，前端不尝试还原。

### 4.3 间距、尺寸与布局

| 类别 | Token / 数值 | 说明 |
| --- | --- | --- |
| 基础单位 | 4px | 所有间距为 4 的倍数 |
| 紧凑 | 4 / 8px | 图标与文字、表格内局部 |
| 控件 | 12px | 控件内边距、行内动作间距 |
| 分组 | 16 / 20px | 表单分组、移动端区块 |
| 页面 | 24 / 32px | 桌面工作区边距 |
| 大区块 | 40 / 48px | 登录、空态、模块分隔；不用于密集表格 |
| 桌面控件高度 | 36 / 40px | 筛选 36px，主按钮和表单 40px |
| H5 触控高度 | 最小 44px | 主要按钮建议 48—52px |
| 桌面表格行高 | 48 / 56px | 普通 / 两行摘要 |
| 命令轨道 | 76px，允许 72—80px | 图标固定，不因放大改变命中区域 |
| 模块导航舱 | 168—184px | 只显示当前模块二级入口 |
| 内容最大宽度 | 1680px | 超宽屏居中，保留阅读线长 |

### 4.4 圆角、边框、阴影

- 小控件 6px；筛选、输入、表格选中行 8px；实体分组 10—12px；玻璃导航/上下文面板 16px。
- 禁止把所有区块做成 24—40px 大圆角卡片。
- 默认 1px 边框 `#D5D9DA`；聚焦或选中可用 2px 强调色，但不得造成布局跳动。
- 数据表格和长表单不使用阴影，只用边框与留白。
- 浮层阴影：`0 12px 32px rgba(82,110,110,.10)`；对话框可增至 `.14`，不使用黑色重阴影。

### 4.5 玻璃层级

| 层级 | 使用位置 | 规范 |
| --- | --- | --- |
| `glass-context` | 顶部案件上下文、登录说明 | 白色 82—92% + `backdrop-filter: blur(12px)` + 1px 白色内边 |
| `glass-command` | 当前模块导航舱 | 白色 76—88% + blur 16px + 轻阴影 |
| `glass-focus` | 宽屏选中案件工作面板、必要浮层 | 白色 88—94% + blur 12px；内部数据区仍用实体白面 |

降级：不支持 `backdrop-filter`、开启减少透明度、低性能设备或打印时，改为 `#FFFFFF` / `#F7F8F8` 实体背景和普通边框。玻璃层不得放在滚动表格、金额明细、附件列表、长表单下面。

### 4.6 图标与工程手绘元素

- 线性图标统一 1.75px 笔画，24px 视觉盒；选中状态可使用实心小底，不改图标位置。
- 管理端优先验证并显式声明 `@element-plus/icons-vue` 后再使用；H5 优先 Vant 自带图标。若未显式安装，则使用项目内受控 SVG，不依赖 Skill 的 React 图标包。
- 禁止 emoji、彩色插画图标和泛化“机器人/AI”符号。
- 电动两轮车工程手绘图、尺寸线和细网格只用于管理端顶部、登录页、空状态或首次流程预览，透明度 8%—18%，`pointer-events:none`。
- 电单车线稿不能进入表格单元格、报价/资金明细、长表单或 H5 密集内容背景。
- 当前参考效果图用于方向参考，不直接当生产资产；正式实现应重绘可控 SVG，并确认素材权属。

## 5. 组件规范

### 5.1 命令轨道与模块导航舱

- 轨道宽 76px，模块图标命中区至少 48×48px；图标和文字基线固定。
- 当前模块点击或键盘激活后展开导航舱；导航舱保持打开，直到选择其他模块、按 `Esc`、点击工作区或显式收起。
- 悬停只允许“预览展开”，离开后延迟 120ms 收起；键盘焦点进入时必须展开，焦点不可被收起动作吞掉。
- Dock 效果只做图标内部 `scale(1.04)` 和背景淡入，轨道槽位不改变尺寸，不推挤相邻入口，不遮挡工作区。
- 当前项同时使用底色、2px 内侧标记和 `aria-current="page"`。

### 5.2 案件队列

- 顶部只放高频筛选：关键字、状态、必要业务筛选、查询/重置；更多筛选进入展开区。
- 服务端分页，默认 20 条；排序必须由 API 或既有稳定顺序提供。前端不能只对当前页假装全局排序。
- 行首使用案件号；第二行可放报案号、车辆、脱敏联系人。状态列始终文字化。
- 选中行用 `accent-soft`、左侧 3px 标记和 `aria-selected`，不使用重阴影。
- 加载使用与实际列宽一致的骨架行；空态说明当前筛选并提供“清除筛选”；失败态在表格原位给“重试”。
- 行点击选中，行内更多菜单阻止冒泡；键盘 `Enter` 打开工作面板，`Ctrl/Cmd + Enter` 进入完整详情。

### 5.3 选中案件工作面板

只放：

1. 案件号、真实状态、车辆/脱敏联系人、保险公司、报案号。
2. 当前流程位置，不创造后端状态。
3. 当前阻塞条件，例如四项维修授权条件。
4. 最近处理历史，完整历史进入详情。
5. 一个明确主操作和至多两个次操作。

以下内容必须进入独立详情：草稿全量编辑、复杂派单/改派、报价明细编辑、OCR JSON/人工复核、批量导入、长资金账本、投诉完整历史、全部附件版本。

### 5.4 表单

- 标签在输入框上方；必填用文字“必填”或 `*` 加可访问说明，不只用红色。
- 帮助文字在控件下方，错误文字占用稳定位置，避免提交时布局跳动。
- 金额输入保留字符串；输入法完成后再校验，不在输入过程中自动改值或舍入。
- 长表单按“案件信息 / 车主与车辆 / 事故信息 / 处理说明”分组；桌面双列，1024px 以下单列。
- 保存动作固定在表单尾部；超过两屏的独立详情可使用底部粘性操作条，但不能遮住最后一个字段。
- 危险动作使用二次确认，并明确对象、影响和不可恢复性；幂等提交期间按钮保持 loading 且不能重复点击。

### 5.5 表格与金额明细

- 表头不透明，必要时在内部滚动容器内 sticky；禁止整页横向无限滚动。
- 数字与金额右对齐，文字左对齐，状态居中或左对齐保持一致。
- 报价必须区分“网点原始报价”“平台正式报价”“最终核损金额”，不得用“最终金额”混称。
- 加价方式、加价值、平台利润只出现在客服/管理员视图；网点和车主 DOM 中不渲染这些字段。
- H5 报价明细按每项两列定义列表呈现，不压缩成桌面表格；车主不出现报价入口。

### 5.6 附件与照片

- 上传区明确类别、格式、10 MiB、每类 20 个有效附件；上传前、上传中、成功、失败、重试、弱网恢复状态完整。
- 每个文件显示文件名、类别、版本、状态、大小和有权操作；替换明确提示“保留旧版”。
- 图片列表使用受控下载生成的临时 Blob 预览，不暴露对象键；下载/预览失败允许重试。
- 完工照片提交后标记“证据已冻结”，不显示替换/作废入口。
- OCR 候选明确标记 `Mock / 候选信息 / 不写入正式业务`；内部 JSON 只在专门复核视图中展示，不作为普通历史组件。

### 5.7 通知、待办与期限

- 桌面顶栏只显示未读/待办入口；展开层使用玻璃，完整列表使用实体页面。
- 待办标题、案件号、期限/不限期、逾期文字和进入案件动作必须同时可见。
- 期限是客服可选字段；不显示系统默认时限，不把逾期渲染成自动状态变化。
- 自动超时、重复提醒、升级和短信均不出现为可用开关。

### 5.8 组件状态矩阵

| 状态 | 表达规则 |
| --- | --- |
| `hover` | 仅细指针设备；背景/边框变化，位移不超过 1px |
| `focus-visible` | 2px `#526E6E` 焦点环 + 2px 白色间隔；不移除原生语义 |
| `active` | `transform: scale(.98)` 或 1px 下压，80ms；不改变布局 |
| `loading` | 按钮保留宽度；列表/表格用结构化骨架；上传显示文件级进度 |
| `empty` | 说明“为什么为空”及一个可执行恢复动作；不伪造数据 |
| `error` | 就近说明、保留用户输入、提供重试；展示安全的 traceId（如 API 已返回） |
| `disabled` | 文字仍可读；若业务阻塞，旁边解释原因，不能只有灰按钮 |
| `readonly` | 实体只读面 + “只读/历史版本”文字；不伪装成 disabled 输入框 |
| `success` | 短时消息 + 页面数据刷新；关键版本操作显示新版本/历史已保留 |
| `warning` | 人工核对、逾期、确认失效；不自动升级为错误 |
| `destructive` | 红色语义、对象和影响说明、二次确认；提交后不可重复触发 |

## 6. 四角色信息架构

### 6.1 管理端模块层级

```text
管理端
├─ 工作台
│  ├─ 我的待办
│  └─ 最近通知
├─ 案件中心
│  ├─ 全部案件 / 我的待办 / 案件草稿
│  └─ 案件详情
│     ├─ 概览与状态历史
│     ├─ 派单与异常
│     ├─ 报价、核损与维修授权
│     ├─ 材料与 OCR
│     ├─ 维修、收车与评价
│     ├─ 资金记录
│     └─ 独立投诉
├─ 价格数据库
│  ├─ 价格候选 / 历史版本
│  ├─ 品牌、车型、配件、别名、适配关系
│  └─ 导入预览 / 批次 / 错误报告
├─ 资金导入
├─ 站内通知
└─ 管理入口（ADMIN）
   ├─ 用户与角色归属
   ├─ 区域、网点与服务区域
   ├─ 审计日志
   └─ 已有规则设置（如疑似重复天数）
```

投诉当前没有全局投诉分页 API，因此第一版不设计虚假的全局投诉台账。管理员从待办进入相关案件的“独立投诉”分区处理；若后续需要独立投诉队列，须先新增并确认真实 API。

### 6.2 角色页面范围

| 页面/能力 | ADMIN | CUSTOMER_SERVICE | REPAIR_SHOP | OWNER |
| --- | --- | --- | --- | --- |
| 角色工作台 | 管理待办、通知、只读案件入口 | 业务待办、通知、案件入口 | 本店任务、通知 | 本人案件进度、通知 |
| 案件列表/详情 | 全部正式案件；草稿按既定权限 | 全部正式案件、本人草稿 | 当前派给本店 | 绑定本人 |
| 建单、派单、异常处理 | 按已确认的管理员例外 | 主要执行者 | 接单、拒单、到店相关动作 | 无 |
| 报价/核损 | 内部只读，可见敏感字段 | 审核、加价、核损、确认 | 本店原始报价；只见门禁布尔结果 | 无入口、无字段 |
| 材料/OCR | 全部只读、审计查看 | 全分类写入、替换、作废、OCR 复核 | 本次派单报价与三类照片 | 三类照片只读 |
| 维修/收车/评价 | 只读 | 代录进度/完工、收车/撤回、评价纠正 | 开修、进度、完工 | 收车、一次可选评价 |
| 资金 | 内部只读、审计 | 目标、流水、冲销、导入、导出 | 本次派单应付/实付与状态 | 无入口、无字段 |
| 投诉 | 状态处理、内部说明 | 追加纠正说明 | 当前派单公开内容 | 创建并看本人投诉 |
| 价格数据库 | 日常运营 + 来源字典 | 日常运营，不维护来源字典 | 无 | 无 |
| 用户/组织/审计 | 有 | 无 | 无 | 无 |

## 9. 核心交互

### 9.1 主从视图与完整详情

1. 用户在队列中选择案件，右面板以 180ms 淡入/平移 8px 切换，URL 同步到该案件，浏览器前进/后退有效。
2. 切换时先保留旧面板轮廓并显示局部骨架，避免整页闪白。
3. 未保存表单不放在快速面板；若完整详情有未保存内容，离开前使用标准路由守卫提示。
4. 主面板仅执行单一步骤；复杂编辑始终点击“打开完整详情”。
5. 404/403/状态冲突在面板原位显示；状态冲突提供“刷新案件”，不静默覆盖用户操作。

### 9.2 维修授权

- 四项条件按固定顺序显示；每项有完成状态、更新时间（API 有时）和可执行入口（角色有权时）。
- 条件不齐：显示缺失原因，开修按钮 disabled；不能新增“报价已审核”“网点确认”“回款已到账”等第五条件。
- 报价、核损金额或核损材料变化导致确认失效时，界面显示“依据已变化，需要重新确认”，并刷新版本号。
- 网点点击开始维修后进入 loading；成功更新为“维修中”，失败保留条件列表和服务端错误。

### 9.3 上传与弱网

- 文件选择后先做本地类型/大小提示，但以后端校验为准。
- 每个文件独立展示：等待上传、上传中、服务器处理中、成功、失败、可重试。
- 弱网断开时保留已选择文件和填写说明，不自动重复提交有副作用的命令；重试复用同一幂等键。
- 离线仅展示“连接已断开”，不伪造成功；恢复后由用户重试或安全刷新。

### 9.4 金额、版本和确认

- 追加版本前显示“旧版本保留”的影响说明。
- 固定金额/比例加价为互斥单选，切换时清空或明确确认旧输入，不同时提交两个字段。
- 资金冲销明确“原流水保留、流水号仍占用、重录需新流水号”。
- 导入预览将有效、待人工、重复、失败分组/筛选；确认只使用已有逐行结果规则，不暗示整批原子成功。

## 10. 动效规范

### 10.1 时长与曲线

| 场景 | 时长 | 动画 |
| --- | --- | --- |
| 按压反馈 | 80ms | `scale(.98)` 或 1px 下压 |
| hover/focus 背景 | 120—140ms | opacity / background |
| 页面/案件切换 | 160—180ms | opacity + translate 8px |
| 抽屉/导航舱 | 180—220ms | transform + opacity |
| 成功状态更新 | 180ms | 图标淡入；不播放庆祝动画 |

统一曲线：`cubic-bezier(.2,.8,.2,1)`；禁止 `transition: all`，只声明实际属性。

### 10.2 磁吸按钮

只允许：桌面细指针设备上的工作台“进入处理”、登录主按钮、空态唯一 CTA。触发条件为 `@media (hover:hover) and (pointer:fine)`，指针进入按钮 24px 邻域后最大偏移 3px，离开立即回正。

不允许：危险操作、表格行内按钮、确认弹窗、金额提交、上传/下载、H5、键盘焦点或触屏。键盘和触屏始终是稳定按钮；`prefers-reduced-motion: reduce` 时完全关闭。

### 10.3 有限滚动接管

日常案件列表、详情、长表单、附件、财务、投诉和 H5 全部保持原生滚动，不得接管。

唯一候选位置是独立的首次“六阶段流程预览/导览”页面：

- 仅用户主动进入或首次显式选择“查看流程导览”时启动。
- 桌面宽度 ≥1280px 且非减少动效时，每次滚轮只吸附到相邻阶段，不横向劫持。
- 页面常驻“跳过导览”；`Esc` 立即退出；方向键、PageUp/PageDown、Home/End 可操作。
- 一旦用户操作表单控件、打开菜单或使用屏幕阅读器，不启用吸附。
- `prefers-reduced-motion`、触屏、宽度 <1280px 或 JS 失败时，退化为普通纵向六段内容。
- 本能力不是 MVP 日常操作所必需，提示词 10/11 默认不实现，除非用户确认要保留导览。

### 10.4 减少动效

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    scroll-behavior: auto !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

不得依赖动画结束才能看到内容或完成操作。

## 11. 响应式规范

### 11.1 桌面宽屏：≥1440px

- 76px 命令轨道 + 174px 当前模块导航舱 + 内容区。
- 工作台内容最大 1680px；案件主从区推荐 42% / 58%，队列最小 420px，详情最小 680px。
- 筛选栏保持一行，高级筛选按需展开；表格正常呈现 5—7 个高价值列。
- 完整详情可使用 240px 内部分区导航 + 主内容，不与全局轨道混淆。

### 11.2 约 1024px：1024—1439px

- 命令轨道保持 72px；模块导航舱默认收起，点击/焦点后覆盖展开，不占持续宽度。
- 案件队列固定 340—380px；右侧摘要去掉次要列和长说明，保留案件号、车辆、状态、阻塞和主操作。
- 复杂表格隐藏低优先列并提供列设置/详情，不用浏览器整页横向滚动。
- 对话框最大宽度 `calc(100vw - 48px)`；长表单改一列或主列 + 辅助说明列。

### 11.3 平板：768—1023px

- 竖屏：主从变为“列表 → 详情”两页，返回保持筛选、页码和滚动位置。
- 横屏且宽度足够：允许 40% / 60% 分栏，但右侧只显示摘要；复杂操作进入全屏详情。
- 全局轨道变为顶部紧凑栏或左侧可关闭抽屉；所有入口可点击、可键盘访问，不依赖 hover。
- 表格转换优先级：关键字段固定的列表行 > 可展开详情行 > 横向滚动。金额明细可在局部容器横滚，但首列和合计保持可见。
- 底部粘性操作区考虑 `env(safe-area-inset-bottom)`，不遮挡最后内容。

### 11.4 手机：360—390px

- 单列，页面左右 14—16px；任何内容不得导致视口横向滚动。
- H5 底部导航 3—4 项，内容区底部预留 `72px + safe-area`。
- 案件列表每项两到三行：案件号/状态、车辆、当前动作或更新时间；服务端分页用“加载更多”或明确页控。
- 桌面表格改成定义列表/分组行；报价每项依次显示项目、数量、单价、行金额。
- 页面底部只放一个主操作；次要动作进入上方实体区或更多菜单。危险动作不和主操作并排。
- 长案件号、文件名、流水号使用 `overflow-wrap:anywhere`；金额不截断，必要时整行显示。
- 上传器先显示压缩预览/文件名，再显示进度；失败项就地重试。
- 输入时考虑软键盘：粘性底栏在键盘打开时取消固定，聚焦控件滚入可视区域。

## 12. 可访问性

- 目标 WCAG 2.2 AA；正文对比度 ≥4.5:1，大字与非文字 UI ≥3:1。
- 桌面完整键盘路径：跳到主内容 → 命令轨道 → 模块导航 → 筛选 → 队列 → 工作面板 → 主操作。
- 使用语义 `nav/main/aside/section/table/form`；状态变更用克制的 `aria-live="polite"`，错误摘要聚焦后仍可返回原字段。
- 图标按钮必须有中文可访问名称；Tooltip 不是唯一名称来源。
- 对话框锁定焦点并返回触发点；抽屉可用 `Esc` 退出。
- 触控目标至少 44×44px；相邻危险动作间距至少 8px。
- 日期、金额、状态不只靠格式或颜色；中文状态和单位始终可读。
- 骨架屏标记 `aria-busy`，不能被读屏当真实数据逐项朗读。

## 13. Element Plus / Vant 映射

### 13.1 Element Plus

- 用 CSS 变量映射 `--el-color-primary`、背景、边框、文字、圆角和控件高度；不复制组件内部 DOM 做脆弱选择器覆盖。
- 案件表格继续使用 `ElTable`、`ElPagination`、`ElForm`、`ElUpload`、`ElDrawer`、`ElDialog`，但统一业务空态、错误态和 loading 骨架。
- `ElDescriptions` 只用于短摘要；长详情改分区定义列表，避免三列内容在 1024px 断裂。
- 原生 `button/input/select/textarea` 逐步替换为 Element Plus 或统一封装的语义控件；不能长期混搭两套视觉状态。
- 表格行选择与侧面板联动时保留真实路由和键盘操作。

### 13.2 Vant

- 使用 `ConfigProvider` 映射强调色、字体、边框和按钮高度；保留 Vant 的触控与安全区能力。
- `Cell` 适合案件摘要和只读定义列表；复杂报价/资金不用多层 Cell 套娃。
- `Uploader` 显示文件级状态；`PullRefresh` 只刷新读取，不自动重放写命令。
- `ActionBar`/底部主按钮必须加安全区；输入法弹出时不遮挡控件。
- 网点和车主共享基础 token，但路由、首页内容和字段组件分别组织，避免在一个模板中堆大量角色条件。

## 14. 现状审计与冲突检查

| 现状 | 设计影响 | 后续实施要求 |
| --- | --- | --- |
| 管理端首页仅按钮卡片，无统一壳层 | 无法形成模块上下文 | 提示词 10 建立 AppShell；不改业务 API |
| 管理端 `body min-width:1024px` | 1024 以下直接不可响应 | 按本规范改为自适应，表格局部响应 |
| 详情把报价、维修、资金、投诉、附件串成长页 | 认知负担和滚动成本高 | 改为摘要 + 深链分区；保留真实组件能力 |
| 多处原生控件与 Element Plus/Vant 混用 | 状态和焦点不一致 | 分端统一组件映射，保留语义和测试选择器 |
| 历史记录部分直接显示 JSON | 业务用户难读 | 转为字段标签、时间线和版本表；开发信息单独折叠 |
| H5 案件列表一次请求 `size:50` 且无页控 | 与列表分页原则不一致 | 使用真实服务端分页/加载更多，不在客户端假分页 |
| 通知面板 sticky details 覆盖页面 | 展开后干扰长表单 | 改为顶栏摘要层 + 独立通知页面 |
| 价格/用户页暴露大量内部 ID 输入 | 可用性差但 API 真实 | 后续用分页选择器/搜索选择，提交仍传 ID |
| 当前金额字符串由后端提供 | 与精度规则一致 | 格式化显示但不重新计算或舍入 |
| 管理端存在真实用户、组织和审计 API，但页面不完整 | ADMIN 入口可落地 | 仅实现现有 API 能力，不扩展角色/配置 |
| 没有全局投诉分页 API | 不能做真实投诉总表 | 通过真实待办深链到案件投诉；新增 API 需另行确认 |
| 首页没有聚合统计 API | 不能做经营指标卡 | 工作台只用待办、通知、案件分页数据 |
| Mock 地图返回合成坐标/直线距离 | 不能呈现为真实导航 | 明示“模拟位置/直线距离”，只在派单辅助区使用 |
| 参考线稿是效果图资产 | 权属和可编辑性未确认 | 生产实现重绘原创 SVG，不直接切图复用 |

权限核对结论：本方案没有新增角色，没有让保险公司登录，没有让车主创建案件/看金额/付款，没有让网点看加价或内部字段，没有把资金变成真实支付，也没有把待办期限变成自动超时。四项维修授权门禁原样保留。

## 16. 已确认的设计取舍（2026-10-10）

用户确认“全部按建议”。以下取舍只影响呈现与导航，不改变业务规则：

1. **管理端模块导航舱**：点击或键盘激活后常驻，hover 仅预览；不采用始终随 hover 开关的方案。
2. **1024px 案件主从布局**：保留 360px 队列 + 摘要面板；平板竖屏改为列表/详情两页。
3. **H5 底部导航**：网点为“任务/案件/通知/我的”，车主为“案件/通知/投诉/我的”；投诉仍需进入具体案件后创建。
4. **首页品牌文字**：暂用“e保 / 保险协作台”作为设计占位，不视为正式产品名或 Logo；正式名称及 Logo 待用户提供后替换，不影响本阶段方案确认。
5. **工程线稿资产**：根据参考方向重绘原创 SVG，不直接使用效果图切片。
6. **六阶段流程导览**：MVP 默认不实现滚动吸附，只保留普通可访问流程说明；如未来确需首次导览，须另行确认后按第 10.3 节约束实现。

以上取舍作为提示词 10 和 11 的设计依据；仍不得擅自采用更强动效、增加全局投诉台账或新增统计指标。按阶段门禁，须由用户明确授权后才开始提示词 10。
