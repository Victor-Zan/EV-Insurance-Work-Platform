## 以后自己启动（独立后台方式）

打开 PowerShell，执行：

```powershell
cd 'D:\01Files\01_study\021\AIE3905\第二阶段网站搭建'
powershell -NoProfile -ExecutionPolicy Bypass -File '.\启动本地网站.ps1'
```

脚本会先检测 Docker 引擎；未就绪时会自动请求启动已安装的 Docker Desktop，并最多等待 180 秒，再等待原 PostgreSQL/MinIO 健康，构建并启动后端，最后启动两个前端。三个服务通过当前用户的无触发器按需任务在独立后台运行，日志各自保存；任务不保存密码，也不会自行开机启动。启动完成后命令返回，可以关闭启动终端。关闭网页不会停止服务。重复运行会复用健康的服务，启动缺失的服务；一个服务退出不会连带停止另外两个。

这仍是本机开发环境，没有配置开机自启。2026-10-28起，第二阶段启动入口使用无窗口宿主，异常退出间隔1分钟、最多自动恢复3次；点击停止入口会取消恢复。重启电脑、主动停止或恢复次数耗尽后，重新执行启动命令。首次构建可能需要几分钟，不要连续重复启动。

## 检查与停止

在上述目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File '.\检查本地网站.ps1'
powershell -NoProfile -ExecutionPolicy Bypass -File '.\停止本地网站.ps1'
```

检查命令显示后端、两个页面及两端 API 代理的 UP/DOWN。全部 UP 后还应实际登录；健康检查不代替业务验收。

停止命令只结束本脚本登记且核验过路径和启动时间的三个网站进程树，保留 Docker、数据库、数据卷和 MinIO 文件。对于之前手工启动、未登记的健康服务，启动脚本会复用，但停止脚本不会结束它们；请到其原终端按 Ctrl+C。

## 进程停止后如何恢复

浏览器可能保留已经加载的登录页；后端停止时页面仍能显示，但登录或加载数据会提示网络连接失败。旧脚本通过 Start-Job 托管三个服务，关闭托管终端或其中一个服务退出时，可能一起停止。本轮已改为独立后台进程，消除这种联动；不据此断言所有退出原因均已消失。

1. 先运行 `检查本地网站.ps1` 确认哪个服务 DOWN。
2. 执行 `启动本地网站.ps1`，等候启动完成。它会启动已停止的服务，复用其余健康服务。
3. 刷新管理端 <http://127.0.0.1:5173> 或 H5 <http://127.0.0.1:5174>，重新登录；需要时按 Ctrl+F5。
4. 若提示“已登记服务仍运行但不健康”，先保留日志；可运行停止脚本，再重新启动。不要批量结束所有 Java、Node 或 PowerShell 进程。

### 重启仍失败时

- **Docker 未就绪**：启动器会自动发现 PATH 或用户目录/Program Files 中的 Docker Desktop 并请求启动，最长等待180秒。若仍未就绪，查看启动器日志和 Docker Desktop/WSL 状态；不要通过清库、删除卷或反复点击启动脚本处理。
- **端口被占用**：脚本不会自动结束未知进程。确认是否有之前手工启动的服务，到原终端停止；无法确认归属时保留错误信息。
- **服务退出或超时**：查看提示的日志。新日志在 `local-validation/website-background-日期时间/`，每个服务都有普通日志及 `-error.log`。旧 `website-*` 日志保留，不会覆盖。
- **健康全部 UP 但密码错误**：网络已恢复，应检查账号密码或由管理员重置；编辑环境变量不会重置已存在账号。

进程登记在 `local-validation/website-processes.json`，包含进程编号、启动时间和日志路径，不保存密码。不要手工填入其他进程编号。
