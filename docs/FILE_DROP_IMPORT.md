# 现有上传入口的文件拖拽增强

本轮仅增强交互。拖入通过原生文件输入的同一个 `change` 事件进入既有处理函数；没有新增上传服务、解析业务、接口、权限、迁移或真实供应商调用。服务端仍是文件与业务权限的最终边界。

## 覆盖清单

| --- | --- | --- |

| 管理端创建工单 → TXT | 单文件拖入与点击都调用原文字读取、提取；不识别聊天图片 | UTF-8 TXT；200000 字节、50000 字符、1000 行 |

## 文件夹与未覆盖项

- 原“选择文件夹”继续使用 `webkitdirectory`，相对路径原样交给已有解析；明确标注暂不支持文件夹拖入。
- 所有拖拽区拒绝目录，不遍历、不解压、不调用目录读取器，也不将目录扁平化后假装成功。无法安全确认拖入内容的浏览器提示改用文件/文件夹选择器。
- 普通照片区不接受 ZIP；ZIP 只在已有建单 ZIP 入口支持，不新增其他 ZIP 业务。
- H5 的 `funds/FundsImportPanel.vue` 仅由客服条件分支引用，而 H5 入口禁止客服登录，当前无可达上传入口；本轮不新增入口或扩大权限。
- 未实现的通用聊天档案/整包业务、企业新格式及其他解析能力不在范围。

## 状态、错误与兼容边界

- 拖入提示、高亮采用嵌套计数；离开、释放、Escape、窗口失焦与拖拽结束会复位。禁用状态变化也会复位。
- 只阻止带 `Files` 的浏览器拖入导航；文字拖动不阻止。不在页面初始化、刷新、悬停时上传、识别或解析。
- 点击与拖入共用文件数量/扩展名/空文件/大小检查，再交给原业务校验。混合非法批次整批拒绝，列出非法文件名和原因；原来已有的文件和手填内容保留。累计数量等仍由原入口校验。
- 展示文件名、字节大小、待处理/处理状态及原入口结果；选择不被标成上传成功。照片真实上传完成由原 `jobs.done` 表示。原预览、移除和重试控件保留，不新增客户端去重/自动重试策略。
- 原始文件输入与键盘可操作按钮均保留；手机继续使用原文件选择、相册等系统能力，不强制拖拽。
- 浏览器需要支持 `DataTransfer`、文件输入赋值及目录项检测；不支持时使用点击选择。目录拖入、Safari/Firefox/Edge、操作系统文件管理器拖放和实体手机尚需对应设备验收，不能从单一内嵌浏览器推断兼容通过。

## 本轮验证与证据

两端分别执行 `npm run lint`、`npm run typecheck`、`npm test`、`npm run build`。新增每端10项传输/组件测试，保留原ZIP、照片累计数量、角色/数据范围、OCR、报价和导入回归；具体最终结果见本轮 PROGRESS。

浏览器使用实际 `TextFormIntake`、`ScenePhotoIntake`、`QuoteOcrPanel`、`ImportView` 组件与合成文件/模拟HTTP适配器，不连接业务数据库。验证：批量照片预览、非法类型不丢原文件、取消高亮、锁定拦截、H5失败后手填保留与原按钮重试、原文件选择器选择CSV后不自动解析。拖拽事件由本地验收页合成，非操作系统文件管理器验收；报价视图限制390px容器，非实体手机。
