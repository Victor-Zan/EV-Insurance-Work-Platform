# 派单页自动定位与合作网点推荐

实施日期：2026-10-25。对应 [实施提示词](AUTO_LOCATION_DISPATCH_PROMPT.md)。仅初次派单使用自动链路；已有改派保留原流程。

## 行为与边界

- 从已接受事故地址定位，已保存的人工接车位置优先；第一步缺地址时可在派单页补填。回车和失焦进入同一处理链。
- 服务端核对启用广东区县、父链、原事故事实、供应商行政区和定位精度。道路级、多解、区域冲突、Mock定位及缺少目录映射均提示更正，不自动取第一项。
- 按原事故区县筛选合作网点和车型资格；按接车点→网点、策略32计算道路距离，最多50家。全部比较完整且相关资料完整才预选第一家；部分结果保留可用距离，需人工选店，不认定全体最近。界面显示本次比较范围和数量。
- 推荐阶段不更新案件事故区县/停车地址、不派单。最终按钮在同一事务内复核版本、位置、网点和有效期，复用原应用服务保存必要区县与接车地址、派单、幂等和审计。疑似重复失败会连同地址/版本/审计一起回滚；原事故地址文本保持。
- `automatic_dispatch_attempt` 每客服/案件保留一个当前请求身份，不存原始地址、供应商坐标、密钥或结果。相同输入复用在途/有效结果；失败、过期或进程重启后需显式重算。新输入替换任务身份，旧结果不能派单。
- 保留当前CONTROLLED/PROVIDER预算、供应商限流、超时和120秒推荐有效期。底图仍需明确点击加载；没有启用设备定位或公开POI门店搜索。
- 页面之外只改必要的地图派单服务、V29迁移、本机迁移目标及文档；建单、报价、维修、资金和H5页面保持检查点版本。

## API

仅 `CUSTOMER_SERVICE` 可用；管理员也不能代替该角色执行自动派单接口。统一响应、错误处理与bearerAuth保持，OpenAPI注解同步。

| 方法与路径（前缀 `/api/v1/maps/cases/{caseId}/automatic-dispatch`） | 用途 |
| --- | --- |
| `POST /` | `{address?,corrected,districtId?,point?,retry,requestKey}`；默认使用案件已接受地址，`corrected=true` 为车辆转移后的接车位置；`point` 为显式地图校点。返回任务状态、位置、比较范围、分页首屏与可空预选网点 |
| `GET /{id}` | 只读复用当前任务并复核版本、资格和有效期，不调用供应商 |
| `POST /{id}/dispatch` | `{shopId,confirmPossibleDuplicate,duplicateReason}`，须 `Idempotency-Key`；沿原派单服务执行最终一次确认 |

任务状态包括 `RUNNING`、`READY`、`PARTIAL`、`NEEDS_REVIEW`、`EXPIRED`。已有 `/maps/recommendations/{id}?page=&size=` 用于候选分页；自动方案不能借旧推荐派单入口绕过最终位置保存。
